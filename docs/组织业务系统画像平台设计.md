# 组织信息化业务系统画像平台 · 设计与实现（AppMonitor Core）

> 目标：在**不在主机上安装任何软件**的前提下（以旁路流量为主、主动探测为辅），
> 为组织内每一个信息化业务系统构建完整画像。画像由**四个库**联动组成：
> **原始指标库 → 次生指标库 → 行为库 → 行为特征库**。
> 实体粒度到 **IP / 某类 IP 特征**（不定位到具体自然人）。
>
> 设计原则：每个库都拆分为若干**聚焦单一职责、低耦合、可复用的独立引擎**；
> 引擎之间**只通过共享的指标存储（按指标名寻址）通信**，从不互相直接引用，
> 因而任意引擎都可独立增删换。

---

## 0. 总体架构

```
数据源(被动/主动)          库一           库二            库三                     库四
┌──────────────┐   ┌───────────┐  ┌───────────┐  ┌──────────────────┐  ┌────────────────┐
│ SPAN/TAP 镜像 │   │ 原始指标库 │  │ 次生指标库 │  │      行为库       │  │   行为特征库    │
│ NetFlow/IPFIX │──▶│ 6 个采集   │─▶│ 7 个派生   │─▶│ 7 个建模引擎(动态) │─▶│ 2 个匹配引擎    │
│ 反代/WAF 日志 │   │ 引擎       │  │ 引擎       │  │ 向量→基线→指纹→   │  │ 规则匹配 +      │
│ 主动探测(探针) │   │           │  │           │  │ 聚类→异常/漂移/序列│  │ 时序关联        │
└──────────────┘   └───────────┘  └───────────┘  └──────────────────┘  └────────────────┘
        │                 │              │                 │                     │
        └───── Observation ┴── RawMetric ─┴─ DerivedMetric ─┴─ EntityProfile/Event ┴─ SignatureMatch
                          （全部落入统一的 MetricStore，引擎按“指标名”读写，彼此解耦）
```

**流水线一拍（tick）的执行顺序**：`原始 → 次生 → 行为 → 特征`。原始引擎吃当拍的
`Observation`；其余每层只读取上一层写入存储的结果。编排器（`Pipeline`）不认识任何
具体引擎，只按层序运行注册表，因此在任何位置新增引擎都只是“注册”动作。

**统一数据模型**（`backend/app/models/schema.py`）：

| 类型 | 含义 | 关键字段 |
|---|---|---|
| `Observation` | 归一化后的一条事件（旁路解码或主动探测） | ts, system, entity, peer, method, L3/L4/L7 字段, reachability |
| `RawMetric` | 原始引擎产出的一个测量值 | name, value, kind, **method(获取方式)**, dims |
| `DerivedMetric` | 由原始指标计算得到的次生值 | name, value, window_s, **inputs(溯源)** |
| `EntityProfile` | 每(系统,实体)的动态行为画像 | fingerprint, baseline, seasonal, archetype, **separability** |
| `BehaviorEvent` | 行为发现（异常/漂移/异常序列） | kind, score, severity, contributors |
| `SignatureMatch` | 命中的行为特征（指标组合→语义） | signature_id, label, category, confidence, evidence |

**获取方式（`AcquisitionMethod`）** 是原始指标的一等公民字段：
`passive_span`（镜像/分光全包解码）、`passive_flow`（NetFlow/IPFIX/sFlow）、
`passive_log`（旁路日志：反代/WAF/LB）、`active_probe`（ICMP/TCP连接/Banner/HTTP）、
`active_dns`、`active_tls`、`derived`（派生）。

**跨网不可达是一等状态**：主动探测的结果用 `Reachability` 枚举表达
（reachable/unreachable/timeout/filtered/degraded），当目标处于跨网/边界之后无法触达时，
记录为 `unreachable/timeout/filtered` 而**不是缺失样本**；下游按“信息”而非“空洞”处理，
基于主动数据构建的画像在链路关闭时可**优雅降级**。

## 库一：原始指标库（Raw Metrics Library）

**定位**：基于流量或其它无需在主机装软件的方式能拿到的、尽可能全的原始指标，
按协议层/获取方式分类，每条都标注**获取方式**。拆分为 6 个采集引擎：

| 引擎 | 层/获取方式 | 主要产出 |
|---|---|---|
| `raw.l2l3` | 网络层 / 被动镜像 | 包/字节量、协议构成(TCP/UDP/ICMP占比)、TTL(最小值,栈/跳数线索)、IPv6占比 |
| `raw.l4flow` | 传输层 / 被动流记录 | 流数、上/下行字节及比、去重对端/端口数、SYN数、重传率、RTT、窗口、流时长 |
| `raw.http` | 应用层 / 被动镜像或反代日志 | 请求数、2xx/3xx/4xx/5xx、时延、请求/响应体、去重路径、GET/POST/写方法占比，**类别型证据**(方法/热点路径/UA/Content-Type 分布) |
| `raw.tls` | 加密元数据 / 被动握手解码(不解密) | 握手数、去重SNI、弱版本占比、握手耗时、**JA3/JA3S 指纹**、SNI/加密套件集合 |
| `raw.dns` | 名称解析 / 被动53口或解析日志 | 查询数、去重查询名、NXDOMAIN率、TXT占比、查询名均长、查询名/类型集合 |
| `raw.active_probe` | 主动探测 | 可达性评分、丢失率、开放端口数、RTT、跳数、**可达状态枚举** |

> 完整可枚举清单见 `data/catalog.yaml`（55 条原始指标，含 `name/category/unit/method/engine/desc`），
> 前端「指标库」页可检索浏览。

**分类维度**（可扩展）：网络层 network、传输层 transport、HTTP、TLS、DNS、主动 active。
类别型分布（`*_set`/`*.methods` 等）以 `CATEGORICAL` 指标存储，供次生的熵/图引擎与
特征库消费；这些引擎完全不需要知道值是怎么来的，只按指标名取用——这是低耦合的关键。

**为什么不装主机 Agent 也够用**：卷积在流量里的信息足以刻画“谁在何时、对谁、用什么协议、
传了多少、成功与否、加密姿态、名字解析行为、时间节奏”。主动探测补齐“对方是否活着、
链路多远、开了哪些口”，并显式处理跨网不可达。

## 库二：次生指标库（Derived Metrics Library）

**定位**：对原始指标做分析或组合分析，派生出新的、更有辨别力的指标。拆分为 7 个派生引擎：

| 引擎 | 方法 | 代表产出 |
|---|---|---|
| `derived.aggregation` | 窗口聚合 | 对任意原始指标的 sum/mean/p95/max/**cv(变异系数)** |
| `derived.ratio` | 跨指标比率 | http错误率、5xx率、成功率、**上传主导度**、字节/流、请求/对端、DNS失败率 |
| `derived.periodicity` | 自相关+变异系数 | **周期性评分(信标识别)**、beacon滞后、**时间规律度**（近窗口，常量节奏=1.0） |
| `derived.entropy` | 香农熵/字符熵 | SNI熵、DNS名熵、路径熵、**DGA评分**(域名字符熵加权)、JA3多样性 |
| `derived.session` | 会话重建 | 会话数、每会话请求数、**思考停顿**、活动占空比（人机区分强特征） |
| `derived.graph` | 通信图形状 | 扇出、**对端新鲜度(相对历史)**、新增对端数、目的集中度 |
| `derived.trend` | 趋势/平滑 | 对关键指标的 EWMA、斜率、**变点分**（近段 vs 前段的稳健z） |

> 完整清单见 `data/catalog.yaml`（24 类次生指标）。

**设计要点**：
- 每个次生引擎都是**数据驱动 + 纯函数式**：给定原始指标名与统计口径即产出，新增一个
  组合指标通常是一行数据改动（如 `ratio` 的规则表、`aggregation` 的目标表）。
- 周期性/规律度使用**近窗口**计算，保证“刚开始信标/刚发生变化”能被当下反映，而不是被
  历史稀释；常量节奏被正确判为“最规律”（信标典型形态）。
- 共享数值工具在 `engines/derived/util.py`（熵、分位、稳健统计、自相关、余弦距离等），
  任何引擎可复用而不产生相互耦合。

## 库三：行为库（Behavior Library）—— 动态生成，不列静态清单

**定位（关键差异）**：行为库**不是一份可枚举的清单**，而是“每个业务系统 × 每个实体
动态生成的行为画像集合”。因此本节给出的是**如何又准又全地识别**的算法，而非条目表。

要满足的能力：
1. 针对**某一个业务系统**，为**某一个用户(IP)** 精确刻画其具体行为画像；
2. 也能把**某一类用户**泛化成一个精准的类画像；
3. 精度尽可能细，且**可区分**——凭画像能把某一个/某一类用户从人群中挑出来；
4. 当某用户当下行为与其**日常行为画像不一致**时，能精准识别。

行为库拆分为 7 个建模引擎，串成“**特征向量 → 基线 → 指纹 → 聚类 → 异常/漂移/序列**”。
共享契约是 `engines/behavior/features.py` 里的 **FEATURE_SPEC（34 维特征向量）**——
一个有序、命名的特征词表；所有行为引擎都按同一下标读写同一向量，因此“改行为特征”是这
一处的数据编辑，而非五个引擎的代码改动（低耦合的核心手段）。

### 3.1 引擎与算法

| 引擎 | 职责 | 关键算法 |
|---|---|---|
| `behavior.feature_vector` | 装配当拍 34 维特征向量 | 读快照→按 FEATURE_SPEC 取值→重尾量取 log1p 压缩；同时把每个分量以 `feature.<name>` 派生序列写回存储（历史落在共享存储，其它引擎经标准API读取，绝不触碰本引擎内存） |
| `behavior.baseline` | 每(系统,实体)稳健基线 + 季节性 | **中位数/MAD**（抗离群），**24 桶时段(ToD)季节基线**；采用**滞后参考窗口**（排除最近 guard 拍），使新变化在“检测时延期”内相对变化前的常态被度量，而非被瞬间吸收 |
| `behavior.fingerprint` | 稳定行为指纹 + **可区分度** | 稳定指纹=历史中位向量；**separability=在同系统内到最近邻指纹的余弦距离(0..1)**，直接回答“凭画像能否把该实体从人群挑出” |
| `behavior.clustering` | 泛化为行为原型(类画像) | 对同系统全体稳定指纹做 **KMeans + 轮廓系数选 k**，并按主导特征**自动命名**原型（interactive/automated/bulk-producer/broad-fanout/high-dispersion…）——新 IP 可即刻归类并对齐类基线 |
| `behavior.anomaly` | 多方法异常打分 | 三探测器融合（见 3.2） |
| `behavior.drift` | “不像它自己了” | 近窗口中位 vs 稳定指纹的 **MAD 缩放余弦距离**，且需**持续多拍**才判漂移——单峰不算 |
| `behavior.sequence` | 行为**顺序**建模 | 以实体触发的特征**类别序列**为一阶马尔可夫链，在线学习(系统×原型)转移矩阵，对新转移计算**惊异度(bits)**，越界跳转即使各指标都正常也高分 |

### 3.2 异常识别算法（又准又全的核心）

`behavior.anomaly` 融合三个相互独立、盲区不同的探测器，避免任何单一方法主导：

1. **稳健 z 距离（主信号，可解释）**：当前向量对每维基线(中位/MAD)的偏离。
   - 对结构性零特征（熵、DGA、丢失率等，常态≈0 且散度≈0）设**较大的绝对下限**，
     避免小绝对变化被放大成巨大 z；z 截断到 ±12。
   - 聚合用“**超过 2.5σ 的累计超额**”而非简单最大值：`strong=Σ max(0,|z|-2.5)`，
     `score=1-exp(-strong/6)`。这样**单个噪声特征无法独自打高分**，真正的异常（外发、
     扫描、爆破）会在多维同时偏离而被凸显。
2. **孤立森林（组合信号）**：在实体自身历史上训练 IsolationForest，捕捉**逐维检验漏掉的
   “特征组合”异常**。为消除其固有误报率，仅当当前点落在训练分布**下 8 分位尾部**才计分。
3. **季节残差（时段信号）**：对时段敏感特征，度量“对本时段而言是否异常”；空/欠支撑的
   时段桶跳过，不臆测。

**融合**：以 z 为主，孤立森林与季节残差作为**加权助推**：
`fused = primary + (1-primary)·combo·(0.4+0.6·primary)`，其中 `combo=max(iso,seasonal)`。
即：助推器单独最多只能抬到阈下，**只有当主信号存在时**才能把发现推到 high/critical——
从而让正常实体保持安静。

**告警质量护栏**：强异常（≥0.8，如外发/爆破）**即时告警**；较弱异常需**上一拍也超阈**方才
告警，避免天然突发型实体的单拍毛刺造成 critical 误报。严重度按分值映射 info→critical。

**为什么能“区分某一个/某一类用户”**：
- 指纹(向量) + separability 提供“个体可辨识度”；聚类原型提供“类画像”。
- 判“不像日常”走两条独立路：`anomaly`（对基线中心的统计偏离）与 `drift`（对**自身指纹形状**
  的持续背离）。前者答“今天这拍离常态多远”，后者答“行为**形态**是否搬家且稳住了”。
- 序列引擎再补“**动作次序**”维度：登录→批量导出（中间无浏览）这类越界次序即便每个指标都在
  各自区间内也会被高惊异度识别。

### 3.3 验证结果（合成多系统流量，注入 5 类威胁）

| 注入实体 | 场景 | 被哪层捕获 |
|---|---|---|
| 10.20.1.13 | 交互用户转为**批量外发(exfil)** | anomaly=1.00 + drift=0.97 + 组合特征“认证后外发” |
| 10.30.2.21 | 账户**凭据填充(bruteforce)** | anomaly=0.99 + 特征`auth_bruteforce` + 序列`write→auth`高惊异 |
| 10.40.4.52 | api 客户端转为**周期信标(beacon)** | 特征`c2_beacon`(时间规律度=1.0) |
| 10.30.2.99 | 新主机**端口/路径扫描** | 特征`port_scan`/`web_path_fuzzing` + 组合“枚举后扫描” |
| 10.20.7.77 | 新主机**DNS 隧道** | 特征`dns_tunnel`/`dga_resolution` |

**5/5 全部捕获，14 个正常实体 0 误报。** 新实体(无基线)由特征库即时捕获，
有基线实体由行为库统计捕获——**分层防御**天然覆盖“冷启动”与“形态渐变”。

## 库四：行为特征库（Behavior Signature Library）

**定位**：不同指标组合“代表什么意思”的**预设库**，用于识别“用户可能在干什么”。
可枚举、数据驱动。拆分为 2 个匹配引擎：

| 引擎 | 职责 |
|---|---|
| `signature.rule_match` | 对每个实体的**扁平指标快照**评估全部在范围内的特征；条件支持硬判定与**模糊隶属(soft 容差带)**，置信=AND隶属加权均 × 最佳OR隶属 × 权重，受 NONE 门控。产出`SignatureMatch`（TA当下在做什么） |
| `signature.correlation` | 把原子命中按**时序**组合成高层活动：`sequence`(有序,窗口内) / `cooccur`(并发)，置信=各构件置信之积。同样数据驱动 |

**特征定义 schema**（`data/signatures/primitives.yaml`，24 条原子特征）：
```yaml
- id: bulk_upload
  label: "批量上传/数据外发"
  category: transfer          # 语义类别
  severity: high
  all:                        # 全部满足(AND)，soft 给模糊带
    - {metric: l4.bytes_up, op: gt, value: 3000000, soft: 2000000}
    - {metric: derived.upload_dominance, op: gt, value: 3, soft: 2}
  none:                       # 排除项(NOT)
    - {metric: derived.timing_regularity, op: ge, value: 0.8}  # 排除计划备份
```
`op ∈ gt/ge/lt/le/eq/ne/between/in/not_in/present`。metric 指向快照中的原始/次生指标名——
匹配引擎**无需知道值的来源**，只按名取用。

**原子特征覆盖的语义类别**（可扩展）：
browse/search/write/api/integration/auth/admin/transfer/streaming/scan/recon/
beacon/tunnel/posture/health/maintenance/sync 等。典型条目：交互浏览、站内检索、表单提交、
API调用、系统集成、登录、**认证爆破**、批量下载/上传、大对象下载、流媒体、**端口扫描**、
**主机横扫**、**Web路径爆破**、**C2信标**、**DNS隧道**、**DGA解析**、弱TLS、服务可达性下降、
后端5xx激增、链路重传高、健康探测、备份同步、后台运维。

**组合特征**（`data/signatures/composite.yaml`，5 条）：
认证后批量外发(auth→transfer)、资产枚举后端口扫描(recon→scan)、信标与隧道并发(beacon+tunnel)、
扫描后认证爆破(scan→auth)、运维后大批量搬运(admin→transfer)。

> 前端「行为特征库」页可检索、查看每条的条件与语义；共 24 原子 + 5 组合。

## 技术实现路径

### 引擎框架（低耦合、可复用的落地机制）
- `core/engine.py`：`Engine` 基类声明 `name/layer/consumes/produces/description`，唯一入口 `run`；
  `Registry` 按层序(raw→derived→behavior→signature)保序管理；`safe_run` 兜底异常不拖垮流水线。
- **运行步频 `interval`**：重型 ML 引擎（基线/指纹/聚类/异常）按步频跳拍执行，保证单拍开销可控，
  且不改变引擎间耦合关系。
- **训练态 `Context.training`**：预热期只建基线/指纹/序列模型，侦测引擎**不产出告警**，避免冷启动噪声。
- **存储即接缝**：`core/store.py` 的 `MetricStore` 是内存环形时序库，接口即
  `add_*/series/latest/snapshot/profile`；生产环境在此处替换 ClickHouse/VictoriaMetrics/Timescale，
  引擎零改动。引擎间**只经存储按指标名通信**，从不相互 import。

### 数据采集适配（生产接入点）
- 被动：SPAN/TAP → 解码器(zeek/suricata/自研)一次性解码为 `Observation`；或 NetFlow/IPFIX 收集器；
  或反代/WAF/LB 旁路日志。解码只做一次，指标逻辑与解包彻底分离。
- 主动：探针发起 ICMP/TCP-connect/Banner/HTTP-HEAD/TLS-cert/traceroute，产出 `method=active_probe`
  的 `Observation`，跨网不可达以 `Reachability` 表达。
- 开发/演示：`pipeline/generator.py` 合成多系统多实体流量（含时段调制 + 注入 5 类威胁 + 漂移场景），
  让四库开箱即有数据、检测可复现；`Runtime.warmup()` 以虚拟时钟在数秒内合成多日历史以建立基线。

### 编排与运行
- `pipeline/orchestrator.py`：`Pipeline.run_tick(observations, now, training)` 跑一拍。
- `pipeline/build.py`：唯一“知道具体引擎集合”的装配处；`Runtime` 负责预热 + 后台实时循环。
- `main.py`：FastAPI 启动即预热并起实时线程；REST 只读投影 + 静态前端托管。

### API（`backend/app/api/routes.py`，只读投影层）
`/api/health` `/overview` `/engines` `/catalog` `/signatures`
`/systems` `/systems/{s}/entities` `/systems/{s}/entities/{e}`（含指纹各维 z、季节、事件、命中）
`/…/series?name=` `/events` `/matches` `/step`。任何端点只读存储、不触引擎——换引擎不破 API。

### 前端（`frontend/`，零依赖原生 JS + 内联 SVG，离线可用）
六视图：**总览**(流水线/KPI/严重度环/类别命中)、**实体画像**(列表按当前异常/漂移排序 → 下钻：
**行为指纹各维 z 偏离条**、当前特征命中“TA在做什么”、行为事件、指标时序浏览)、
**行为事件流**、**行为特征库**(可检索)、**指标库**(原始+次生,含获取方式)、**引擎拓扑**(22引擎产出/消费/说明)。

### 部署与扩展
- 水平扩展：按业务系统/网段分片流水线；存储层替换为分布式时序库；模型训练可离线批处理后回灌
  基线/指纹/聚类结果（`EntityProfile`）。
- 新增能力=新增一个引擎并注册；新增指标=改 `catalog`/`ratio` 数据；新增语义=改 `signatures/*.yaml`。

## 完备性自检（对照需求再反思）

| 需求点 | 落地 | 评估 |
|---|---|---|
| 库一：尽量全的原始指标、按分类、含获取方式 | 6 引擎 + 55 条目录(method 一等字段) | ✔ 覆盖 L3/L4/HTTP/TLS/DNS/主动；类别型证据齐备 |
| 含主动探测且考虑跨网不可达 | active_probe + `Reachability` 枚举 | ✔ 不可达/超时/过滤为一等状态，可降级 |
| 库二：分析/组合派生的次生指标 | 7 引擎 + 24 条目录 | ✔ 聚合/比率/周期/熵/会话/图/趋势 |
| 库三：动态、不列清单、给准且全的识别算法 | 7 引擎 + 3.2 融合算法 | ✔ 向量→基线→指纹→聚类→异常/漂移/序列 |
| 到 IP/一类 IP，不定位到人 | entity=IP/IP类；无自然人标识 | ✔ |
| 能区分某一个/某一类用户 | separability(个体) + 聚类原型(类) | ✔ |
| 日常不一致能精准识别 | anomaly(离基线) + drift(离自身指纹,需持续) + sequence(越界次序) | ✔ 5/5 注入命中,0 误报 |
| 库四：指标组合→语义的预设库,识别在干什么 | rule_match + correlation；24 原子 + 5 组合 | ✔ 数据驱动、模糊匹配、时序组合 |
| 每库拆多个聚焦、低耦合、可复用引擎 | 22 引擎，仅经存储按指标名通信 | ✔ interval/training/store 接缝 |
| 引擎/后台/前台开发 | 引擎全实现 + FastAPI + 原生前端 | ✔ 端到端可运行、可截图验证 |

**已识别的可增强项（后续演进方向，非缺口阻断）**：
1. **加密载荷内容**不可见——已用 TLS 元数据 + JA3/JA3S + SNI + 时序/体量弥补；可再引入
   加密流量分类模型(FlowPic/nPrint 类)增强应用识别。
2. **季节基线**在演示的快速预热下每时段样本偏少——已通过“空桶跳过 + 助推降权 + 持续性护栏”
   规避误报；生产环境累积真实多周数据后季节维度会更强。
3. **实体身份漂移**（DHCP/NAT 导致 IP 复用）——可加“身份稳定性”引擎，用指纹突变+租约时间做
   实体切分（框架已支持新增引擎）。
4. **图谱级横向行为**——当前 graph 引擎为每实体扇出/新鲜度；可增全局通信图引擎做社团/路径分析。
5. **在线学习稳态**——聚类/序列模型当前在线增量；可增“概念漂移守护”定期重训与版本化。
