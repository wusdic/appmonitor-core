# 组织信息化业务系统画像平台 · 设计与实现（AppMonitor Core）

> 目标：在**不在主机上安装任何软件**的前提下（以旁路流量为主、主动探测为辅），
> 为组织内每一个信息化业务系统构建完整画像。画像由**四个库**联动组成：
> **原始指标库 → 次生指标库 → 行为库 → 行为特征库**。
> 实体粒度到 **IP / 某类 IP**（不定位到具体自然人）。
>
> 设计原则：每个库都拆分为若干**聚焦单一职责、低耦合、可复用的独立引擎**；
> 引擎之间**只通过共享的指标存储（按指标名 / 模型名寻址）通信**，从不互相 import，
> 因而任意引擎都可独立增删换。
>
> 本文描述**当前代码**与**最近一次实测的真实结果**（2026-10-01）。行为库（库三）按用户对第三个库的要求重新组织：
> 以**渐进式、以模式为中心的画像内核**（P00–P15）为主——不遍历所有用户与服务器，由粗到细、越用越准地学到一类行为乃至某一个 IP 的行为，
> 并随行为变化而变化；原有的统计引擎库（B01–B30，节拍不变双粒度模式）作为画像的侧面与检测器族，决策链由两者共用。
> 行为库的英文规格、存储契约与评估细节见 `docs/lib3/`：
> `progressive.md`（渐进画像内核：需求追溯、算法、引擎卡片、门限、集成修订与实测）、
> `architecture.md`（分层设计）、`engines.md`（逐引擎规格与实现备注）、`cadence.md`（双粒度设计 v2.1）、
> `contract.md`（存储契约）、`helpers_api.md`（共享数学库）、`eval.md` / `generator.md`（统计引擎库的评估门限与合成数据）、
> `integration.md`（集成记录、性能与各轮评估）、`decisions.md`（放弃的方案与风险）、`summary.md`（现状摘要）。

## 0. 总体架构

```
数据源(被动/主动)        库一               库二              库三                               库四
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌───────────────────────────────┐  ┌──────────────┐
│ SPAN/TAP 镜像 │  │  原始指标库   │  │  次生指标库   │  │            行为库              │  │  行为特征库   │
│ NetFlow/IPFIX │─▶│ 8 个采集引擎  │─▶│ 7 个派生引擎  │─▶│ 渐进画像内核 P02–P15（14）：   │─▶│ 2 个匹配引擎  │
│ 反代/WAF 日志 │  │ 含动作令牌 R2 │  │ D0 窗口/D1 瞬时│  │ 事件→模式树→约束→群组→一致性→  │  │ 规则匹配 +    │
│ 主动探测(探针) │  │ 客户端栈 R3   │  │ D2 会话       │  │ 视图与侧面；统计引擎 B01–B30   │  │ 时序关联      │
│              │  │ +P00 行为事件 │  │ +P01 事件上下文│  │（27 个已注册）；共用决策链     │  │              │
└──────────────┘  └──────────────┘  └──────────────┘  └───────────────────────────────┘  └──────────────┘
        │                │                 │                        │                           │
   Observation ──── RawMetric / evt.batch ── DerivedMetric / evt.ctx ── model.ptree·pviews / BehaviorEvent / Incident ── SignatureMatch
                  （全部落入统一的 MetricStore；引擎只按“指标名 / 模型名”读写，彼此解耦）
```

**流水线一拍（tick）**：`Pipeline.run_tick(observations, now, training, dt)` 按层序
`raw → derived → behavior → signature` 运行注册表，层内按注册顺序执行；`ctx.window_s = Δt`，
每拍以生成器/采集器的虚拟时钟 `now` 打时间戳。编排器不认识任何具体引擎；
唯一“知道引擎集合”的地方是 `backend/app/pipeline/build.py::build_registry()`。

**统一数据模型**（`backend/app/models/schema.py`）：

| 类型 | 含义 | 关键字段 |
|---|---|---|
| `Observation` | 归一化后的一条事件或一条聚合流记录（旁路解码或主动探测） | ts, system, entity, peer, method, L3/L4/L7 字段, reachability, `extra`（count、bytes_*_total、ts_sample 等） |
| `RawMetric` | 原始引擎产出的一个测量值 | name, value, kind, **method(获取方式)**, dims |
| `DerivedMetric` | 由原始指标计算得到的次生值 | name, value, window_s, **inputs(溯源)**, dims |
| `EntityProfile` | 每 (系统, 实体/类) 的画像容器 | archetype(=类路径), separability, `extra.*`（模型状态、画像、风险原因等） |
| `BehaviorEvent` | 行为发现与事件通知 | kind, severity, p_value, **e_day**, axes, p_by_detector, incident_id |
| `Incident` | 事件（唯一的通知单位，实体或类） | 状态、严重度、证据、解释、叙述、活动链 |
| `Label` | 分析员反馈 | verdict ∈ {tp, fp, expected_change, benign_known, unsure}, scope |
| `SignatureMatch` | 命中的行为特征（指标组合→语义） | signature_id, label, category, confidence, evidence |

**获取方式（`AcquisitionMethod`）** 是原始指标的一等公民字段：
`passive_span`（镜像/分光全包解码）、`passive_flow`（NetFlow/IPFIX/sFlow）、
`passive_log`（旁路日志：反代/WAF/LB）、`active_probe`（ICMP/TCP 连接/Banner/HTTP）、
`active_dns`、`active_tls`、`derived`（派生）。

**跨网不可达是一等状态**：主动探测结果用 `Reachability` 枚举表达
（reachable/unreachable/timeout/filtered/degraded）；目标位于跨网/边界之后无法触达时记为
`unreachable/timeout/filtered` 而**不是缺失样本**，下游按“信息”处理，链路关闭时画像优雅降级。

**“缺失即数据”贯穿全链路**：原始引擎只为本拍有观测的实体发数且打 `ts = ctx.now`；
次生瞬时指标只在全部输入新鲜时才发（D1），窗口指标在零填充的墙钟网格上计算（D0）；
行为库把陈旧计数视为 0、陈旧比率/均值视为 NaN；检测器输入陈旧时写 NaN 而**绝不写 p = 1**。

## 库一：原始指标库（Raw Metrics Library）

**定位**：基于流量或其它无需在主机装软件的方式能拿到的、尽可能全的原始指标，
按协议层/获取方式分类，每条都标注**获取方式**。拆分为 8 个采集引擎（`backend/app/engines/raw/`），渐进画像内核开启时另有行为事件构造引擎 P00：

| 引擎 | 层/获取方式 | 主要产出 |
|---|---|---|
| `raw.l2l3` | 网络层 / 被动镜像 | `l3.bytes_total`、`l3.pkts_total`、协议构成(TCP/UDP/ICMP 占比)、`l3.ttl_min`、IPv6 占比 |
| `raw.l4flow` | 传输层 / 被动流记录 | 流数、上/下行字节及比、去重对端/端口数、`l4.syn_count`、`l4.pkts_total`、重传率、RTT、窗口、流时长；**完整集合** `l4.dport_set`、`l4.peer_set` |
| `raw.http` | 应用层 / 被动镜像或反代日志 | 请求数、2xx/3xx/4xx/5xx、`http.get_count`、`http.write_count`、时延、请求/响应体、去重路径、方法占比；类别型证据 `http.top_paths`/`http.methods`/`http.user_agents`/`http.content_types` |
| `raw.tls` | 加密元数据 / 被动握手解码(不解密) | 握手数、去重 SNI、弱版本占比、`tls.handshake_ms_avg`、JA3/JA3S 集合、SNI 集合及 **eTLD+1 聚合** `tls.sni_etld1_set` |
| `raw.dns` | 名称解析 / 被动 53 口或解析日志 | 查询数、去重查询名、NXDOMAIN 率、`dns.txt_count`、`dns.qname_len_avg`、查询名/类型集合及 eTLD+1 聚合 `dns.qname_etld1_set` |
| `raw.active_probe` | 主动探测 | 可达性、丢失率、开放端口数、RTT、跳数、`probe.state`（可达状态枚举） |
| `raw.action_token`（R2） | 应用层细粒度动作 / 被动 | 模板化动作令牌 `act.tokens`、时间有序动作流 `act.stream`（含 stack_id、`act.stream_frac`）、`act.events`（静默实体零填充）、对象 ID `act.objs`（HLL）、稀有目的地事件 `act.rare_events`、`act.distinct_templates`、`act.new_template_ratio` |
| `raw.client_stack`（R3） | 客户端/设备指纹 / 被动 | `client.stack_set`（ja3n\|UA 族/主版本\|OS\|TTL 类\|TCP 窗口类）、带时间戳的 `client.stack_events`、`client.ua_set`/`ja3n_set`/`ttl_set`/`os_ua_ttl_pairs` |
| `raw.event`（P00，仅渐进内核） | 行为事件 / 被动镜像或反代/WAF 日志 | 每系统每拍一个事件批 `evt.batch`：每条请求/连接/查询（聚合记录按 `extra.ev_sample` 展开）的开放属性表——全部非默认 Observation 字段、`extra.meta` 的每个标量、请求体与查询串键值（`body.kv.*`、`q.kv.*`）、请求头（`hdr.*`）、R2 路由模板、R3 客户端栈；取值保留策略（机密只留形状）、可信代理的来源解析、分层学习抽样与 HT 权重（3.2、3.3.2） |

**v2 升级要点（R1）**：
- **加权记录**：接受 NetFlow/IPFIX 式聚合记录，`w = extra.count`；字节/重传总量取 `extra.*_total`，均值按 w 加权。
- **完整集合**：类别集合由旧的 top-8/12 截断改为 **top-64 + `__other__`**，各值之和等于真实总数；SNI 与 qname 另按 eTLD+1 输出。
- **新鲜性契约**：只为本拍有观测的实体发数，`ts = ctx.now`；`store.add_raw` 维护 first_seen/last_seen。
- **伪实体防护**：以 `__` 或 `class:` 开头的实体被丢弃并计入健康记录。
- **双粒度输入（v2.1 规范模式）**：可合并的去重计数草图 `l4.peer_ids`、`l4.dport_ids`、`tls.ja3_ids`、`act.template_ids`（SetSketch：≤256 键时为精确 64 位哈希集合，否则 1024 字节 HLL），以及每 15 分钟槽的事件计数 `act.slot_events`，供行为库在任意节拍下精确重建小时/刻粒度的去重计数与活动时段。

**R2 动作令牌**：HTTP 令牌 = `METHOD host 模板(path) | 状态类`；TLS（无 L7）= `SNI eTLD+1 : dport + 大小类`；
DNS = `qtype + 模板化 qname`（高熵/长/多数字标签 → `{rnd}`）；纯 L4 = `协议/服务 + 大小类`。
模板化使用 Drain-lite（`engines/behavior/lib/template.py`）：掩码数字/UUID/hex/日期/邮箱/base64/ID，
每 (系统, host, 方法) 一棵深度 ≤ 6 的前缀树，>40 子节点且头部份额 <0.5 的节点变为 `{var}`，
每系统词表上限 4000（Space-Saving 淘汰到 `{rare}`）。每实体每拍最多 512 行动作流，超出时按会话块水库抽样并写 `act.stream_frac`。
`act.new_template_ratio` 仅在系统词表满 24 h 后才写（避免空词表首拍把 1.0 学进基线）。

> 目录 `data/catalog.yaml` 收录 55 条原始指标（`name/category/unit/method/engine/desc`，
> 其中 42 条 passive_span、7 条 passive_flow、6 条 active_probe），前端「指标库」页可检索浏览。
> 行为库专用的输入序列（R1 新增集合、`act.*`、`client.*`、`*_ids`、`act.slot_events`）不在目录中，
> 其语义与保留期见 `docs/lib3/contract.md`。

**采集扩展（渐进内核）**：`Observation.extra` 中可选的 `l7`（请求体前 4 KB、体长、查询串、请求头）、`ev_sample`（聚合记录内最多 64 条逐事件行）、`meta`（适配器/WAF 任意字段）与 `sample_rate`（传感器抽样率），`models/schema.py` 不变，其他原始引擎忽略它们（契约见 `docs/lib3/contract.md` N 节）。

**为什么不装主机 Agent 也够用**：流量中已包含“谁在何时、对谁、用什么协议与客户端、做了什么动作(模板化)、
传了多少、成功与否、加密姿态、名字解析行为、时间节奏”。主动探测补齐“对方是否活着、链路多远、开了哪些口”，
并显式处理跨网不可达。

## 库二：次生指标库（Derived Metrics Library）

**定位**：对原始指标做分析或组合分析，派生出新的、更有辨别力的指标。
拆分为 7 个派生引擎（`backend/app/engines/derived/`），按新鲜性语义分为三组；渐进画像内核开启时另有事件上下文引擎 P01：

| 组 | 引擎 | 方法 | 代表产出 |
|---|---|---|---|
| D0 窗口 | `derived.aggregation` | 6 h 墙钟**零填充网格**上的窗口统计（计数型的空拍为 0、测量型为 NaN） | `derived.<metric>.{sum,mean,p95,max,cv}` |
| D0 窗口 | `derived.periodicity` | 零填充计数网格的自相关与变异系数 | `derived.periodicity_score`、`derived.beacon_lag`(秒)、`derived.timing_regularity` |
| D0 窗口 | `derived.trend` | 12 h 网格上的 EWMA、斜率与分半 Welch z | `derived.<metric>.{ewma,slope,changepoint}` |
| D1 瞬时 | `derived.ratio` | 跨指标比率，仅当输入全部新鲜才发，分母为 0 不发 | http 错误率/5xx 率/成功率、**上传主导度**、字节/流、请求/对端、DNS 失败率，各带 `.n`（分母） |
| D1 瞬时 | `derived.entropy` | 完整 64 项集合上的香农熵 | SNI/路径/DNS 名熵、**DGA 评分**、JA3 多样性，各带 `_n`；`derived.dns_dga_named_n` |
| D1 瞬时 | `derived.graph` | 通信图形状，已见对端集合 30 天衰减 | `derived.new_peer_count`、`derived.dest_concentration`、`derived.fanout`、`derived.peer_novelty`（后两者仅供库四） |
| D2 会话 | `derived.session` | 基于动作流时间戳重建会话 | `derived.activity_duty_cycle`（24 h 时间加权）、`derived.think_time_s_avg`（会话内间隔中位数，仅新鲜时）、`derived.session_count`、`derived.req_per_session`；规范模式另发 `derived.think_log_sum`/`derived.think_gaps` |
| 事件上下文（P01，仅渐进内核） | `derived.event_context` | 给 P00 的每个事件补上下文；为活跃 IP 按小时粒度生成指标窗口事件 | `evt.ctx`：本地分钟、星期、日类型、节假日类别（工作日/周末/节假日/调休）、月日、月末、会话 id/位置、前一路由与动作、思考时间；`evt.win`：每个 (系统, IP, 小时) 一个事件，属性 `m.<指标名>` 为任意新鲜原始/次生指标（新指标当天进入画像，3.3.2） |

> 目录 `data/catalog.yaml` 收录 24 类次生指标。

**设计要点**：
- 共享纯函数 `engines/derived/fresh.py`（网格/新鲜读取）与 `engines/derived/util.py`（熵、分位、稳健统计、自相关）；
  引擎之间不相互引用。
- **不再重新盖戳陈旧输入**：旧实现把任意年龄的最新值重新盖上 `ts=now`，导致 duty_cycle 只有 0/1、think_time 恒为 0；
  v2 中瞬时指标只在输入新鲜时发出，窗口指标以墙钟网格描述包括空闲在内的真实活动。
- 周期性在少于 8 个网格点时**不写**（而不是写 0），避免把 0 学成点质量。
- **规范（双粒度）模式**下 duty_cycle、periodicity、timing_regularity 改在固定的 15 分钟槽网格上计算（数据来自
  `act.slot_events`），因此与节拍长度无关，在 3600 s 节拍下也有定义；tick 模式保持 v2 行为（黄金测试）。

### 3.0 需求与对应机制（逐句追溯）

需求原文共 21 句（逐句表见 `docs/lib3/progressive.md` §3），这里按含义合并。最后一列是包 O 上的实测状态（详见 3.8）。

| # | 需求（摘） | 机制 | 引擎 | 实测状态 |
|---|---|---|---|---|
| S1 | 不能遍历所有用户和服务器的行为，参数多、数据量大时会耗尽资源 | 学习单元是**行为事件**，不是“实体 × 指标”；每个业务系统（或系统族）一棵有节点预算的**模式树**；所有计数放在有界、带衰减的草图中；每个事件的代价是 O(树深 × 触及节点)；学习按分层抽样限额；按 IP 的状态只有例外、绑定的重击者和有上限的 LRU；运行同一应用的服务器归为**系统族**、共用一棵树 | P00、P04、P12、P15 | 内存对 IP 数的对数斜率 0.085、对服务器数 0.21（达标），对属性数 0.23（目标 0.2，未达标）；每事件绝对耗时超目标 10–20 倍 |

### 3.1 总体结构：渐进画像内核 + 统计引擎库

**为什么改。** 原行为库（B01–B30）以“每个 (系统, IP) × 固定 52 维特征 × 每拍”为单位建模：
每个实体独立维护基线、检测器、校准环与检查点，成本与内存随“IP 数 × 指标数”线性增长
（实测约 9.4–11.7 MB/实体、约 15 ms/实体·拍，`docs/lib3/integration.md` §9.2）；指标集合写死在 `lib/features.py` 中；
画像的粒度（个体 / 角色类）是预先规定的。在组织包 O（约 700 个来源 IP）上，B01–B30 与渐进内核一起运行时，
存储在第 4 天就达到 2.26 GB，两次 21 天运行分别在 4.4 GB 与 7.1 GB 时被内存上限杀掉（`progressive.md` §16.2 M25）——
这正是需求所说的“遍历所有用户会把资源耗死”。

**现在的结构。** 行为库由两部分组成，仍然只通过 `MetricStore` 按指标名/模型名通信：

1. **渐进画像内核（Progressive Profile Core，PPC，P00–P15）** —— 画像本身。从行为事件学到模式、约束、群组与陈述，
   并对每个事件按“最具体的已确认模式”打分，报告“不一致”。
2. **统计引擎库（B01–B30）** —— 现在是画像的若干**侧面**与**检测器族**：节律、客户端栈、身份、链接、预算等仍由它们提供；
   决策链 B23–B30（反馈、校准、融合、风险、事件单、治理、解释、画像）由两部分**共用**；
   在有界模式下逐 IP 模型只给“挣得”它的 IP（3.5）。

**一拍的数据流**（`docs/lib3/progressive.md` §4.2；注册顺序见 3.4）：

```
Observation ─► [raw]     R2 动作令牌、R3 客户端栈 ─► P00 事件构造 ─► evt.batch（每系统一批，开放属性、请求体键值、抽样权重）
            ─► [derived] D2 会话 ─► P01 事件上下文 ─► evt.ctx（本地时刻/日类型/会话/前一动作）+ evt.win（指标窗口事件）
            ─► [behavior]
                 P15 资源治理（预算、活跃集、挣得集；读 t−1）
                 B01–B18、B21（统计引擎；有界模式只处理活跃集/挣得集）
                 P02 属性注册 ─► model.attr          P05 属性选择（每小时）─► model.attrsel
                 P03 一致性（用 t−1 的模型给本拍每个事件打分，前序）─► pat.assign、behavior.score[conf_*]、pattern_violation
                 P04 模式树（学习 t−D 的事件，按信任加权）─► model.ptree
                 P06 数值界 / P07 载荷语法 / P08 绑定 / P09 时间窗 ─► model.pbounds / pgrammar / pbind / pwin
                 P10 业务流程 ─► model.pflow      P11 谁的发现（每日）─► model.who_groups      P12 系统刻画与策略（每日）─► model.sysprof、model.sysfam
                 B23 反馈、B24 校准（含 conf_*）、B25 融合、B26 风险、B27 事件单、B28 治理、B29 解释
                 P13 侧面 ─► model.facets / 画像侧面树    P14 视图 ─► model.pviews（系统视角、群组视角，中英文陈述）    B30 画像
            ─► [signature] rule_match、correlation
```

三个闭环各自带迟滞与稳定 id：P11 群组 → IP 层次的 `grp` 级 → P04 按群组分裂 → 更清晰的模式 → P11 签名；
P05 的保留集 → P04 的目标 → 节点熵 → P05 的效用；P12 的策略 → 哪些引擎运行 → 实测效用 → P12。

**设计原则**（`progressive.md` §4.1 的 PPC-1…PPC-11）：

1. **学事件，不学实体行。** 画像单元是一次请求/事务/流/会话步骤。
2. **先泛后细，证明了才细。** 每个系统从根模式开始；细化只在其证据超过自身描述长度（MDL）时存在；单 IP 模式只作为“例外”。
3. **构造上有界。** 每个结构都有声明的上限（节点、学习叶、草图大小、属性、样本、签名），超限按明确的效用淘汰，从不静默截断。
4. **开放模式（schema）。** 代码里没有“有哪些属性”的清单；类型、层次与角色都是推断并版本化的。
5. **处处前序（prequential）。** 每个模型先给事件打分、再从中学习；同一个“前序码长”同时用作分裂证据、漂移信号、属性效用、挣得模型检验与策略效用——统一的货币是“比特/事件”。
6. **只学可信的。** 学习权重 = 事件质量 × 该 IP 上一拍的 trust（B28）；被隔离 IP 的事件暂存而不学习。
7. **只经存储耦合。** 不 import 其他引擎；共享数学在 `engines/behavior/lib/p*.py`。
8. **用自然单位解释。** 每条约束都能渲染成带支持度、置信度、首末次出现与版本的句子。
9. **质量不等于证据。** 聚合权重、抽样（HT）权重与传感器采样率只放大“质量”（分布估计），从不放大“证据”（检验、界与置信度）。
10. **服务器也不遍历。** 运行同一应用的系统共用一棵树；按活跃度分配内存与周期任务；周期拟合只处理有新证据的节点。
11. **随时有效。** 随数据到来反复检查的结构决定（分裂、例外、用于高危的封闭性）使用在连续监视下仍有效的检验（e 值与 Ville 不等式）。

**注册方式**（`backend/app/pipeline/build.py::build_registry(progressive=…)`，`REGISTRY_MODES`）：

| 模式 | 引擎数 | 内容 | 用途 |
|---|---|---|---|
| `full`（默认） | 44 | 库一 8 + 库二 7 + B01–B18、B21、B23–B30（27）+ 库四 2；**不含任何 P 引擎**，`conf_*` 检测器列保持 NaN | Runtime / API、A–E 包、smoke、mini、tick 模式黄金测试 |
| `full+progressive` | 60 | `full` + P00–P15，按 `progressive.md` §9.1 的顺序插入 | 规格中的生产形态；在包 O 上因内存未能跑完 21 天 |
| `progressive_only` | 18 | R2、R3、P00、P01、P02–P15 | 伸缩实验（O-scale、O-servers） |
| `progressive_decision` | 24 | `progressive_only` + B24–B28、B29（决策链） | **包 O 的全部实测** |

`full` 之外的模式由配置 `progressive.enabled`、包的 `registry_mode` 或显式参数开启。Runtime（`backend/app/main.py`）默认仍运行 `full`；
以环境变量 `APPMON_PROGRESSIVE=decision`（或 `only` / `full`）启动时，改在组织包（默认 O）上运行对应注册模式，预热 `APPMON_PROGRESSIVE_DAYS`（默认 7）天后转入实时，
P14 的视图经 v3 API 与前端“画像模式”页展示（3.3.14）。

### 3.2 数据模型

**行为事件。** 两类事件，每类在每个系统各有一棵模式树：`txn`（一次 HTTP 请求、无 L7 的 TLS 连接、DNS 查询或 L4 流，P00 产生）与
`win`（(系统, IP, 小时粒度决策拍) 的指标窗口，P01 产生；其属性 `m.<指标名>` 是该 IP 当拍新鲜的任意原始/次生指标，因此**新指标出现当天就进入画像**）。
事件批 `EventBatch`（`lib/pevent.py`）是列式稀疏结构：时间、IP、质量 w、学习入选概率 π、标志位，以及开放属性表。

**属性命名**：`<命名空间>.<路径>`，命名空间有 `net`（`net.src` = 来源 IP，`net.dst` = 服务器 `peer:dport`，字节、时长……）、
`http`（方法、主机、`http.route` = R2 的路由模板、状态……）、`tls`、`dns`、`client`（客户端栈）、`body`（`body.keys`、`body.kv.<键>`、`body.len`）、
`q`（查询串键值）、`hdr`（请求头）、`meta`（适配器/WAF 的任意字段）、`ctx`（本地时刻、日类型、节假日类别、月末、会话序号、前一路由、思考时间）、
`sess`（会话 cookie 的 HMAC）、`m`（窗口事件的指标）。**缺失也是一个值**：某属性通常存在而本事件没有时取保留值 `⊥`，
因此“GET 没有请求体”可以被学到，而“适配器不再发送某个头”会被识别为模式变更而不是行为变更。

**采集扩展**（只走 `Observation.extra`，`models/schema.py` 不变）：`extra['l7']`（请求体前 4 KB、请求体长度、查询串、请求头）、
`extra['ev_sample']`（聚合记录内最多 64 条逐事件行，使“90 % 在 1–2 KB”在 NetFlow 式聚合输入下仍可学）、`extra['meta']`、`extra['sample_rate']`。
**取值保留策略**（`progressive.value_policy`）：口令、令牌、验证码等按键名通配与取值随机性只保留“形状”，超过 64 字符的值保留形状与长度，其余明文
（需求示例本身要显示 `username=jack`）；可按通配改为 HMAC。**谁的解析**：配置了可信代理 `trusted_proxies` 时取 `x-forwarded-for` 中最右侧的非可信地址；
未配置而单个来源承载系统 ≥ 90 % 流量且其后有 ≥ 50 种客户端栈或会话键时标为 `snat_suspect`，系统以“IP 不作为特征”运行并在视图中给出配置提示。

**质量与证据。** 质量 m_e = 一行代表多少真实事件（聚合份额 × HT 权重 × 采样率），用于分布与渲染；
证据 ω_e ∈ (0, 1] = 这一行带来多少独立信息（3.3.4），用于一切检验、界与置信度。

**泛化层次**（`lib/phier.py`；`gen(a, ℓ, v)` 把取值映射到第 ℓ 层代表，最后一层是 `*`；标“学到”的层由模型给出并版本化）：

| 属性类型 | 层次 |
|---|---|
| IP（`net.src`） | /32 → /24 → /16 → `grp` 行为群组（学到，P11）→ `reg` 区域（配置的 `ip_classes`/`dhcp_scopes`，否则 P11 的前缀覆盖）→ `*`；IPv6 为 /128 → /64 → /48；NAT/共享终端 IP 映射为 `shared:<ip>` |
| 路由 | 原始路径 → R2 模板 `http.route` → 前两段 → 第一段 → 主机 → `*` |
| 时间 | 本地分钟 → 15 分钟槽 → 学到的系统时间窗（P09，如 `w:0900-0921`）→ 时段 → 日类型 → `*`；另有 `ctx.dayclass`（工作日/周末/节假日/调休）、`ctx.dom`、`ctx.mend` |
| 数值 | 取值 → 8 分位箱（对数尺度时取对数）→ 4 分位箱 → 中位二分 → `*` |
| 文本/载荷 | 取值 → 形状（字符类游程，如 `jack` → `L4`）→ 长度分桶的形状 → 字符集 + 长度桶 → 长度桶 → `*` |
| 类别 / 序数 / 集合 | 取值 → 学到的取值组 → `*`；集合 → 模板（去掉稀有元素）→ 基数桶 → `*` |

**模式节点**（`lib/pnode.py`、`lib/ptree.py`）：上下文（从根起的约束合取）、可选的分裂（属性、层级、取值组 + `other` 分支，未见值总落入较泛的模式）、
单 IP 例外、生命周期状态、三个半衰期的质量与证据、谁摘要（每个 IP 层级一个带衰减的 Space-Saving(8) + HLL）、时间摘要（工作日/非工作日 × 96 个 15 分钟槽，
需要时加分钟级加权水库）、≤ 8 个目标属性的摘要（类别：Space-Saving(16)；数值：t-digest + 矩 + 30 天日极值环 + 超越值水库；文本：形状与取值重击者、长度直方图）、
每 IP 每小时次数分布 `rate.ip_h`、不变式、绑定计数、漂移检测器与每日参考快照。所有数值存放在每节点一个 float32 数组里。

### 3.3 算法

本节按规格（`docs/lib3/progressive.md` §6）给出算法与公式；集成中因实测失败而改动的地方在相应位置以 M 编号标注（完整列表见 3.8.6 与 `progressive.md` §16.2），所列默认常数的理由见 `progressive.md` §7.1。

#### 3.3.1 有界、带衰减、可合并的草图（`lib/psketch.py`）

前向衰减（Cormode 等 2009）：时刻 t、权重 w 的条目以 `w·2^((t − L)/H)` 存储（L 为基准时刻），在时刻 T 读出 `存储值·2^(−(T − L)/H)`；
因此衰减在更新时是加法、读取时是乘法，和仍是线性的（可合并、可减去）。每个计数器同时保存三个半衰期
**H_s = 1 天、H_m = 7 天、H_l = 30 天**，用于检验与置信度的计数器另带一份证据。

| 草图 | 用途 | 保证 |
|---|---|---|
| 衰减 Space-Saving(k) | 类别目标、谁的各层级、路由/取值重击者、流程边、按 IP 签名 | 计数误差 ≤ N/k；份额 > 1/k 的条目一定在表中；`count − error` 是保证的下界 |
| HLL(p) | 节点的去重 IP 数、属性基数 | σ ≈ 1.04/√2^p |
| t-digest(δ = 50) | 数值目标、注册表分箱 | 秩误差 O(q(1−q)/δ) |
| Count-Min | 高基数文本值的首见估计 | 高估 ≤ εN（概率 1 − δ） |
| ADWIN、Page–Hinkley | 节点对数损失漂移、目标均值漂移 | ADWIN 每次检验误报 ≤ δ |
| 加权水库（A-ExpJ） | 分钟级到达时刻、P05 探针样本、暂存事件 | 精确的不放回加权抽样 |

分层重击者（谁摘要）的条件计数 `cond(p) = count(p) − Σ_{q 为 p 的重击者后代} count(q)`。全文统一的**未见质量**估计（Good–Turing 加淘汰修正）：

```
U = (N1 + E + 0.5) / (N + 1)
    N  = 置信通道上的证据（不是原始质量），N1 = 只出现约一次的条目数，E = 因表满而被挤出的到达证据
```

人群流动时 E 增大、U 偏大——对“封闭性”是保守方向：流动的人群永远不会显得封闭。

#### 3.3.2 事件构造与有界学习抽样（P00、P01）

P00 把每条 Observation（展开 `ev_sample` 后每行一个事件）的所有非默认字段、`extra.meta` 的每个标量叶、请求体（表单 / JSON 前 64 叶 / multipart / XML 路径集合，
否则 Drain 模板）与查询串变成属性，路由用 R2 模板器的只读接口 `Templater.apply_path` 渲染，然后应用取值保留策略。
**打分（P03）看到每一个事件；学习（P02、P04、P10、P11）只看一个分层样本**，使每拍学习代价 ≤ `E_learn = e_rate·Δt`（默认 e_rate = 10 事件/秒/树）。
分层键为（通道, 该系统树根所分裂属性的取值），根尚未分裂时用（路由 | SNI | 查询名 | 服务器）引导。阈值抽样（Duffield–Lund–Thorup）：

```
π_i = min(1, τ / c_k(i)),   τ 满足 Σ_k min(c_k, τ) = E_learn      （Σ c_k ≤ E_learn 时 τ = ∞，全部学习）
入选事件的质量 = w / π_i      （所有计数、分位与重击者估计保持无偏；稀有动作总被学到）
```

P01 给出本地时刻、日类型（含节假日与调休）、会话（间隔阈值取自 B10 的会话间隔，否则为对数间隔直方图的 Otsu 谷值，夹在 [60 s, 2 h]）、
会话位置、前一路由与思考时间；在小时粒度决策拍为活跃 IP 生成窗口事件（每系统每粒度 ≤ W_max = 512 个，超出时按优先级抽样，
被标记、被隔离、新出现或挣得的 IP 优先 10 倍）。每个窗口事件读取 P05 保留的指标与一个按 crc32 相位轮转的切片（共 96 个），每个注册指标每天至少被探测一次。

#### 3.3.3 属性注册与自动特征选择（P02、P05）

**P02 属性注册**（`model.attr`）：新名字在出现的那一拍登记（发 `attribute_new`），其余统计只从 t − D 的可信学习行更新（攻击者的第一个小时不能移动分箱边界）。
每个学习事件最多更新 A_ev = 32 个属性记录（保留属性 + 其余属性的均匀抽样，HT 加权）。类型规则：≥ 99 % 能解析为 IP → ip；时间戳 → time；
集合 → set；≥ 98 % 可解析为数且去重 ≥ 16 → numeric（否则 ordinal；`status/code/port/…` 等名称提示与“数值序对目标无信息”的数据检验使其成为类别）；
去重 ≤ 256 → categorical；否则 text（键值或 JSON 结构占比 ≥ 0.8 时下一拍起按结构再解析）。
覆盖率在正常流量下跌到长期覆盖率 5 % 以下满一个正常日的属性被宣布 `gone`：其上的分裂折叠、不再参与打分——“适配器不再发送某个字段”不会被当成全系统的行为漂移。
每系统（族）最多 512 个属性。

**P05 属性选择**（每小时，`model.attrsel`）在分层探针样本 R_p = 4096 行（每层至少 min(32, 层大小) 行）上，对属性 a 在层级 ℓ 计算：

```
CR(a)     = max_{c ∈ C0} (1 − H(a | c) / H(a))                       可预测度（被上下文压缩的比例）
U_t(a)    = cov(a) · S_a · (H(a) − min_c H(a | c)) − λ_c · cost_us(a)  作为“目标”的效用，比特/事件
U_s(a, ℓ) = Σ_{b ∈ 目标} Î(b ; gen(a, ℓ)) − (card(a, ℓ) − 1) · K̄ · log2(n) / (2n)   作为“分裂候选”的效用
g3(a → b) = 1 − Σ_x max_y c(x, y) / n                                近似函数依赖误差（Kivinen–Mannila）
          S_a = 1 − JSD(p_{H_s}, p_{H_l}) 为稳定性，λ_c = 0.001 比特/µs（每事件省 1 比特值 1 ms CPU）
```

| 角色 | 条件 | 作用 |
|---|---|---|
| 不变式 | H(a) ≤ 0.05 比特且覆盖 ≥ 0.99（节点内：头部取值占 ≥ 99.5 % 且置信通道证据 ≥ 30） | 只存一次（如服务器地址、“总含 username=”），只检查违规，不建模、不分裂 |
| 分裂候选 | max_ℓ U_s ≥ 0.05 且该层基数 ≤ 64 | 可在最佳 1–2 个层级上细化 |
| 目标 | U_t ≥ 0.05、覆盖 ≥ 0.05、稳定性 ≥ 0.7 | 在节点摘要中建模（每节点前 8 个） |
| 仅形状 | 去重率 ≥ 0.5 且原值层可预测度 < 0.05 | 标识符、随机数、自由文本只保留形状 |
| 冗余 | 与某保留属性 g3 ≤ 0.01 | 不作目标（避免重复计算分裂证据），依赖作为事实交给 P08/P14 |
| 丢弃 | 两种效用都 < 0.02 | 只留在注册表；每 7 天复评一次 |

升级阈值 0.05、降级阈值 0.02 且须连续 3 次；每小时只评估“已有角色的属性 + 64 个轮转属性”，每个属性每天至少评估一次。
当 IP 在 /32、/24、grp、reg 各层的 CR 都 < 0.02 时，`net.src` 被移出该系统的分裂候选与目标——这就是“IP 直接不作为特征”。
（集成修订 M14：注册基数 ≤ 16 且覆盖 ≤ 25 % 的局部字段保留为目标，例如财务审批意见“同意/退回”。）

#### 3.3.4 模式树：证据、前序码长与分裂（P04）

**证据单位**（同一来源在同一叶上的连续事件不是独立证据）：

```
ω_e = trust(ip) · damp(e) / (r + 1)，然后 r ← r + 1      （r = 该 (ip, 会话键, 叶) 自上次间隔 > 300 s 以来已学的行数；ω_e ≤ 1）
```

一次 k 行的突发只贡献约 ln k + 0.58 个单位；行的质量不进入 ω（一行代表 40 个未观测事件，它的信息仍只是一次观测）。
（M7：连续不停顿的来源每满 1 小时也重新计数，否则每 60 秒一次的健康检查 21 天后证据仍只有 7。）

**节点预测**（单层层次 Dirichlet，按证据缩放）：

```
p_N(v) = (s_N(v) · n_N + α · p_parent(N)(v)) / (n_N + α),   α = 2
         s_N(v) = v 在 N 的质量份额（H_m），n_N = N 的证据；根节点回退到注册表中该属性的系统分布
```

**前序码长与分裂统计。** 学习叶为最多 C = 6 个候选 c = (属性, 层级) 记录：每个取值槽 j（Space-Saving(8) + `other`）、每个目标 t、每个分箱 b 的证据加权计数 n_{c,j,t,b}。
对每个学习事件，先用尚未见过它的预测给它编码，再更新：

```
ℓ_leaf,t(e) = −log2 p_leaf,t(b_t(e))
ℓ_c,t(e)    = −log2 [ (n_{c,j,t,b} + α·p_leaf,t(b)) / (n_{c,j,t,·} + α) ]          j = 事件在候选 c 下的取值槽
G_c        += ω_e · Σ_t (ℓ_leaf,t(e) − ℓ_c,t(e))                                  按 c 分裂能节省的比特（MDL 收益）
```

**分裂规则**（每满 n_g = 32 个证据单位检查一次；c1、c2 为收益最高的两个候选，k 为该叶的第 k 次检查）：

```
(V) 有效性：log2 e_c1 ≥ τ0 + log2 C_ever，      τ0 = 10，C_ever = 该叶曾跟踪过的候选总数（只增不减）
             e_c = (1/T_c) Σ_t e_{c,t}           对目标取平均；规格形式 e_{c,t} = 2^(L0_{c,t} − L1_{c,t})，
             L0 = 合并计数下的最大似然码长 Σ_b n_{c,·,t,b}·log2(n_{c,·,t,·}/n_{c,·,t,b})，L1 = 分裂下的前序码长 Σ ω_e·ℓ_c,t(e)
(G) 收益：  G_c1 − L_split(c1) ≥ 0                L_split = log2 C + g·log2 card(a, ℓ)（g 个取值组）
             （实现为选择性收益 Σ_t max(0, G_{c1,t}) − T_c ≥ L_split，见下文 M4）
(S) 稳定：  μ_c1 − μ_c2 ≥ ε_k  或  ε_k ≤ τ_tie = 0.05 比特/单位
             ε_k = sqrt(2 V ln(3/δ_k)/n) + 3 R ln(3/δ_k)/n,  δ_k = δ/(k(k+1)),  δ = 1e-4      （时间一致的经验 Bernstein 界）
(D) 多样：  证据跨 ≥ 2 个本地日期，或 ≥ 200 个证据单位
(M) 质量：  ≥ 2 个取值组各有 ≥ 5 个证据单位
```

**为什么 (V) 随时有效。** 零假设：在该叶上目标 t 的分布与候选 c 的取值无关、证据单位条件独立。每个 e_{c,t} 在零假设下是从 1 出发的非负上鞅
（每个因子的条件期望 ≤ 1，用到 ω ≤ 1 与 Jensen 不等式），由 Ville 不等式 `P(sup_n e ≥ 2^τ) ≤ 2^−τ`；多个 e 过程的平均仍是 e 过程，**无论目标之间如何相关**。
第 i 个候选总以 ≥ τ0 + log2 i 的阈值检验，所以一个叶**在任意频繁的检查下**误分裂到无关候选的概率 ≤ 2^−10 · H(C_ever)（调和数；150 个候选约 0.5 %）。
检查节奏 n_g 只影响 CPU，不影响统计有效性。

**集成后的实现**（`lib/pevalue.py`；`progressive.md` §16.2 M1–M6）：
- M2：规格中的 e 值用“合并后的最大似然码长”作零假设，会先偿还零模型的参数遗憾（约 (k_b − 1)/2·log2 n 比特/目标），OA 登录节点按 /24 区分三个部门的分裂在 101 个证据单位后仍只有 log2 e = 5（仅用户名就省了约 45 比特）。
  实现改为**分块 k 样本 e 过程**：块 = 本地日；块开始时冻结每个取值槽的预测（槽自身平滑计数与叶预测的贝叶斯混合），块内结果按槽预测与“所有槽预测的证据加权混合”（对“无依赖”的投影）之比编码；
  对任何零分布每块因子的期望 ≤ 1，Ville 不等式照样成立。原形式保留为 `log2_e_ui` 供诊断。零检验：60 天内 sup log2 e ≥ 5 的比例 ≤ 2^−5 + 0.02（200 次运行）。
- M1：交易树的根先按**路由做多路划分**（出现 ≥ 3 行、跨 ≥ 2 个日期的路由立即得到自己的子节点），这一划分不是学到的分裂、不剪枝；路由是需求中的“页面/路由”，是动作的标识而不是待检验的假设。
- M3：P05 改了目标列表时，学习片段被“重定目标”而不是清零（被删目标的 e 过程财富转给新目标，自融资组合仍是 e 过程）。
- M4：收益 (G) 只计入被预测的目标（上式），一个只预测用户名的分裂不会被十个无关目标的小负值否决。
- M5：子节点继承其证据单位、出现日期，以及按 `net.src` 分裂时的谁摘要与绑定计数；M6：7 天内的子节点不参与剪枝评判。

**取值分组。** 提交分裂前贪心合并取值槽：合并代价 `ΔL = L_KT(j ∪ j') − L_KT(j) − L_KT(j')`（KT 码长）≤ log2 card(a, ℓ) 时合并，证据 < 5 的槽并入 `other`。
结果就是“{192.168.1.21, 192.168.1.23, 10.168.7.121} 一组、其余 IP 为 other”或“{综合部} / {财务部} / other”这样的取值组。

**复杂度。** 每个学习事件：路由 O(D)；谁/时间/证据更新 O(7D)；目标更新 O((2 + ρ̄(D − 2))·m_t)（繁忙的祖先节点以速率 r_target = 1 事件/秒对目标做稀疏更新，质量按 1/ρ 补偿）；
分裂统计 O(C·(m_t + 2))。默认 D ≤ 8、m_t = 8、C = 6 时至多约 110 次计数更新与 60 次对数——与 IP 数、注册属性数都无关。

#### 3.3.5 泛化：剪枝、合并、修订与预算

- **剪枝**：内部节点保存其分裂在 H_m 上的衰减前序节省 `G_N^m = Σ ω_e(ℓ_N(e) − ℓ_child(e))`，连续 3 次日检 < 0 则折叠（摘要可合并）；分裂属性被宣布 `gone` 时次日即折叠。
- **兄弟合并**：两个子节点在全部目标上的质量加权 JSD < 0.02 比特连续 3 天，则合并（两个部门行为趋同后不再分开）。
- **修订（EFDT）**：每树最多 16 个大内部节点为替代候选保留分裂统计；某替代的收益在相同事件上超过当前分裂 τ0 比特且 (S) 支持时重新分裂，新子节点确认后旧子树退休——例如早期按 /24 的分裂在群组出现后被按 `grp` 的分裂替换。
- **预算**：节点数超过分档上限 N_max（XS 32、S 256、M 1024、L 4096）时先剪效用最低的叶（`u = 其在父节点每日收益中的份额 × (已确认 ? 2 : 1)`），过期叶优先。

#### 3.3.6 例外：某一个 IP 何时得到自己的模式

在已确认节点 N 上，谁摘要中份额 ≥ 2 % 的重来源（最多 16 个，`shared:<ip>` 除外）各有例外统计。例外是 N 按指示变量 `net.src = x` 的分裂，用同样的 (V) 检验（“留出 x”的保守构造）：

```
L1_x,t = x 的事件在 x 自己的预测（回退到 N）下的码长 + 其他来源在 N 自身前序码下的码长
L0_x,t = N 的合并最大似然码长,       e_x = (1/T) Σ_t 2^(L0_x,t − L1_x,t)
例外 ⇔ log2 e_x ≥ τ0 + log2 i_x  且 x 的置信通道证据 ≥ 10 且跨 ≥ 2 天      （i_x = x 在 N 上被检验的序号）
```

例外子节点只保存 x 与群组不同（单目标节省 ≥ 2 比特）的目标，其余继承 N；衰减节省连续 3 天 < 0 则撤销（IP 回到群组）；例外 ≤ N_max 的 10 %。
**绑定不是例外**：“三个 IP 各自提交自己的用户名”是群组节点上的一条函数依赖（3.3.8），不是三个节点。
在开放的大人群（门户）中，单个 IP 在路由节点上达不到 2 % 份额，因此不会出现单 IP 例外（实测门户例外占比 0，达标）；按 IP 的滥用由强度检查捕获（3.3.10）。

#### 3.3.7 生命周期、置信通道、漂移与抗投毒

**生命周期**：

| 转换 | 条件 |
|---|---|
| 新建 → 候选 | 由分裂、修订、交替子树或例外产生 |
| 候选 → 确认 | 置信通道证据 n_c ≥ 20、≥ 3 个本地日期，且每个适用的拟合器（P06–P09）已发布约束或声明不适用 |
| 确认 → 稳定 | 确认 ≥ 7 天、≥ 5 个日期、7 天内无漂移告警 |
| 确认/稳定 → 演化中 | ADWIN 或 Page–Hinkley 告警；接受或替换后回到稳定 |
| 任意 → 过期 | 只计正常日时，期望到达数 E = rate_Hl × 活跃时长 ≥ 3 而一次未见（e^−E < 0.05），发 `pattern_absent` |
| 过期 → 退休 → 休眠 | 过期 30 天退休；日期位图显示 ≥ 3 次规律间隔（月度、季度，间隔变异系数 ≤ 0.2）则转为休眠，400 天内再出现时直接复活（`pattern_revived`），不当作新动作 |

**置信通道（“越久越准”而不冻结）。** 固定指数衰减会让证据饱和：每天 r 个证据单位的节点在半衰期 H 下最多持有 `r·H/ln 2` 个单位。
若用 H_m = 7 天，财务审批节点（每工作日约 3–4 单位）会停在约 30 个单位，未见 IP 质量约 0.016，永远达不到 U ≤ 0.01 的封闭——与“用的时间越长越精准”相反。因此：
- **形状**（分布、区间、时间窗、取值集合）用 H_m（临时约束用 H_s），一到两周内跟随行为；
- **置信度**（封闭性 U、绑定下界、覆盖界、p 值所用 Dirichlet 浓度中的 n、陈述置信度）用 H_l = 30 天的证据，**在接受变化或节点替换时重置为 H_m 状态**，属性处于演化中时以 H_m 值为上限。
行为不变时置信度持续增长约两个月（平台 = rate × 43 天）；接受变化后从新行为重新累积，而不是把两种状态混在一起。

**漂移与接受。** 每个已确认节点对其逐事件对数损失跑 ADWIN（δ = 0.002）：结构漂移时在节点上下文上生长交替子树（Hoeffding 自适应树），≥ 3 天且 ≥ 100 单位后码长更短 τ0 比特才替换，14 天内未胜出即丢弃（每系统 ≤ 4 个）。
每个数值目标与到达分钟跑 Page–Hinkley（λ = 5σ，容许 0.5σ）：节点转为演化中，P06/P09 用 H_s 统计拟合临时约束；变化持续 T_persist（只计正常日：数值区间 1 天、时间窗 3 个工作日、谁集合 2 天、绑定 5 个事件跨 ≥ 2 天），
并且由 ≥ max(2, ⌈0.5·|谁集合|⌉) 个 IP 一致表现（如部门统一改作息）——或单 IP 节点持续 5 天——且这些 IP 期间无打开事件、未被隔离时，才**接受**：约束切换（内容版本 + 1）、该属性的置信通道重置、发 `pattern_drift`。
接受前，一致变化引起的违规封顶为 LOW；单个 IP 的变化不封顶。

**谁集合的变化是特殊的**（抗“慢速投毒”，异常 A9）：仅凭持续出现，外部来源**永远**不会成为谁已封闭节点的成员。新来源只在以下情况被吸收：
(i) 它属于已在该节点有质量的群组（同部门同事）；(ii) 它是某成员的换址候选；(iii) 分析员标注；(iv) 节点敏感度 < 2 且同一群组 ≥ 2 个新来源持续 T_persist。
在此之前它的事件被“降权学习”，每天出现都会再被判为 who 违规。

**信任门控与降权。** P04 学习 t' ≤ t − D 拍的事件（D = max(4 拍, 600 s)），学习质量 = `w/π × trust(ip, t−1) × damp(e)`，证据 ω 带同样的 `trust × damp` 因子。
被 P03 判为 p_ev ≤ 1e-4（相对已确认节点）的事件以 damp = 0.1 学习（M18：凭证被可信地绑定到另一来源、或正在另一处并发使用的取值同样降权），单个来源移动已确认约束要多花十倍时间；
扫描器与随机路径洪泛同样被降权，填不满树。被隔离 IP 的事件进入暂存（每 IP ≤ 256、每树 ≤ 65 536），治理释放时以 trust_prov 学习，拒绝或 7 天过期时丢弃。

**参考快照（双锚点）。** 每天 04:00，无漂移、无暂存事件、主要来源无打开事件的已确认节点把拟合好的约束复制为参考快照；P03 对两者打分并取 `p = min(1, 2·min(p_cur, p_ref))`，
使“当前统计缓慢蠕变”无法掩盖相对参考状态的偏离（与 B04 的双锚点规则相同）。

#### 3.3.8 内容、时间与流程约束（P06–P10）

**P06 数值区间与硬界**（每小时，只拟合“脏”节点）：在变换尺度（`log` 属性取对数）上

```
band90 = [Q(0.05), Q(0.95)]             “90 % 在 …”（形状，H_m）
range  = [当前置信段各日最小值的最小, 各日最大值的最大]，  n_rng = 这些日子观测到的证据单位数
P(下一次 ∉ range) ≤ 2 / (n_rng + 1)     （可交换性：下一观测在 n_rng + 1 个观测中的秩）
尾部   = Q(0.90) 之上（及 Q(0.10) 之下）超越值的 GPD（≥ 30 个超越值时）
```

显示时端点按 1-2-5 × 10^k 网格向外取整，且取整后的经验覆盖仍在 [0.88, 0.95]；“全部在 [a, b]”只在 n_rng ≥ 30（界 ≤ 6.5 %）且近似事件占比 ≤ 0.2 时渲染，
并附“n = 183，下一次落在区间外的概率 ≤ 1.1 %”，界随 n_rng 变紧，否则写“观测范围”。打分：band98 之内用 t-digest CDF 的双侧 mid-p，之外用 GPD 尾部或保形秩 `(1 + #{更极端}) / (n + 1)`。

**P07 载荷语法**：

```
必含键 R = {k : 出现率 ≥ 0.99}，  可选键 O = {k : 0.01 ≤ 出现率 < 0.99}
p(新键) = (N1_keys + 0.5)/(N + 1)，  p(缺少必含键 k) = (miss_k + 0.5)/(n + 1)
```

取值语法：按“骨架”（不含游程长度的字符类/字面量序列）归组；≤ 3 个骨架覆盖 ≥ 99 % 质量时语法为它们的并，并按游程给出长度范围（反统一），共享前缀的骨架被因式分解：
`L4`、`L3`、`L5 . L1` → `[a-z]{3,5}(\.[a-z])?`；否则泛化为字符集并集 + 总长度范围。精确值覆盖 ≥ 99 %、N1/N ≤ 0.01 且 n_c ≥ 50 时取值集合封闭。
**长度上下界来自观测并带覆盖界，不预设**：需求中的“后边不超过 10 个字符”是一个**输出**——jack/rose/mike 三个值学到的是更紧的 `[a-z]{4}`，长度到 10 时才会出现 `{…,10}`；
分析员可经 B23 把业务规则（≤ 10）钉住，钉住只放宽、不收紧。语法外的取值得 p = 未见形状质量 U_s；含语法字符集之外的字符（引号、`=`、空格、`<`、`;`、`--`）标 `injection_shape`。

**P08 绑定（近似函数依赖）**：候选对 (X, Y)：X 为谁的层级（ip、/24、grp）以及 `client.stack`、`sess.key`，Y 为类别/文本目标（从不是口令等仅形状属性），
H(Y) ≥ 0.5 比特、g3(X → Y) ≤ 0.2（或每个 x 的取值集合很小）；每系统 ≤ 16 对。在置信通道证据上拟合：

```
y*_x = argmax_y c(x, y),  k_x = c(x, y*_x),  n_x = c(x, ·)
先验 Beta(a0, b0) = Beta(m·s, (1 − m)·s)：对同节点“其他”重 x' 的留一经验贝叶斯，m = (Σ k_x' + ½)/(Σ n_x' + 1)，s = min(20, 矩估计强度, Σ n_x')
LB_x = Beta(a0 + k_x, b0 + n_x − k_x) 的 5 % 分位
绑定(x) ⇔ n_x ≥ 5 且 LB_x ≥ 0.8；   函数依赖成立 ⇔ 绑定覆盖重 x 质量的 ≥ 80 % 且 g3 = 1 − Σ k_x / N ≤ 0.05
集合绑定 ⇔ 无单值绑定，但 x 的取值集合封闭（U_x ≤ 0.05，≤ 4 个值覆盖 ≥ 95 %）：共享终端“192.168.5.7 → {jack, rose}”，反向为服务账号“svc_backup ← {10.1.1.5, 10.1.1.6}”
```

借用同节点其他 IP 的强度使小部门的绑定几天内就能确认：另两名成员各有 5 次纯登录时，第三个 IP 5 次纯登录即有 LB ≈ 0.88。
违规：函数依赖与绑定成立而 y ≠ y*_x 时 `p_bind = (b0 + n_x − k_x)/(a0 + b0 + n_x)`；y 恰是另一 IP 的绑定值时标 `cross_binding`（凭证轴：192.168.1.21 提交 `username=rose`）；
反向（y 的来源集合封闭而 x 不在其中）标 `foreign_source`，并做**并发检验**：y 的绑定来源在 ±1 小时内在同节点活跃 → `concurrent_use`（凭证同时在两处使用）；
来源是从未见过的 IP 且 y 的绑定来源当天未出现 → `readdress_candidate`（DHCP/VPN 换址，严重度封顶 LOW，并提示 P11 把新 IP 并入旧 IP 的群组）。
**合法改名**：新值 y' 在 ≥ 2 个正常日内有 ≥ 5 次来自可信、未暂存事件的出现，且 x 最近 5 个事件中没有旧值 → 绑定切换（`binding_changed`）。

**P09 时间窗**（每 6 小时，只拟合脏节点）：在节点的 96 槽直方图（需要时用分钟水库）上，于最低密度处展开环形时间轴，做 Bayesian Blocks（Scargle 2013；
块适应度 `N_k(ln N_k − ln T_k)`，先验 `ncp = 4 − ln(73.53·p0·n^−0.478)`，p0 = 0.05），速率 ≥ 3 倍背景（总质量/1440 每分钟）的相邻块合成时间窗，丢弃 < 5 % 质量的窗。
系统根的时间窗成为时间层次的学到层（如 `w:0900-0921`），P04 可以按它分裂。到达时刻的 p 值是该日类型密度下的最高密度区域 p：

```
f(s) = (h(s) + α_t/96) / (N + α_t),   α_t = 0.1，h(s) = 槽 s 的质量份额 × N，N = 该日类型的置信通道证据
p_when = Σ_{s: f(s) < f(s_obs)} f(s) + ½ Σ_{s: f(s) = f(s_obs)} f(s)
```

空槽的密度小但不为零：相对 60 个证据单位的 09:00–09:21 登录，03:05 的登录约得 8e-4，并随观测天数增加而更强。节假日按非工作日密度、调休日按工作日密度打分。

**P10 业务流程**：动作 = （路由模板, 内容变体），每系统一个动作字典（id 永不复用）；会话状态（每拍、全部事件）记录前一动作与间隔；
直接跟随计数只来自 t − D 的可信学习行（攻击者的会话在被判定前不被学习），范围为全系统与每个 ≥ 2 IP 的活跃群组。每 6 小时挖掘：

```
dep(a ⇒ b) = (|a>b| − |b>a|) / (|a>b| + |b>a| + 1)      保留 dep ≥ 0.8、|a>b| ≥ 10 证据单位、占 a 出边 ≥ 5 % 的边（启发式挖掘，Weijters–van der Aalst）
流程 = 从起始动作沿保留边的极大简单路径（≤ 8 个动作），每条边的间隔带 = 其间隔直方图的 [q10, q90]，时间锚 = 各动作的 P09 时间窗
requires(b, a) ⇔ c(b) ≥ 15 且 Beta(½ + c(b 前有 a), ½ + c(b 前无 a)) 的 5 % 分位 ≥ 0.85
p_seq = min(1, 2·min(p_trans, p_req)),   p_req = (c(b 前无 a) + 0.5)/(c(b) + 1)
```

P10 只在 P12 判定会话可识别的系统上运行，其他系统 p_seq 为 NaN。

#### 3.3.9 “谁”的发现（P11）

1. **签名**：每个 IP 一个 Space-Saving(24)，条目为（树键, 动作），只从可信学习行更新；`shared:<ip>` 无签名；最多 50 000 个 IP（按最近活动 LRU）。
   以网段为“用户”的系统按 /24 贡献条目，`none` 模式的系统不贡献。（M12：只用时间上下文的模式条目，地址分裂的上下文会让条目重述地址。）
2. **相似度**（每日）：改进的一致加权抽样（ICWS）加权 MinHash，k = 64；LSH 16 段 × 4 行给出候选对，每个 IP 保留 Ĵ ≥ 0.2 的前 10 个；图为互为 kNN 图。
3. **社区**：Louvain（分辨率 1，确定性顺序），最终层为群组层；两次日运行之间新 IP 达到 10 个证据单位后按其 LSH 邻居的加权多数（≥ 0.6）加入（一步标签传播）。
4. **稳定 id**：对成员 Jaccard 做匈牙利匹配（J ≥ 0.3 继承），IP 要连续两次被分到别处才移动。
5. **名称**：流量只能告诉“谁和谁属于一起”，不能告诉这个组叫“综合部”。配置 `who_group_names: [{name, ips | cidrs}]`（运维配置，或由 IPAM / DHCP 作用域 / 资产台账 / 目录导出写入）
   按成员 Jaccard ≥ 0.5 把名称挂到群组上；否则用自动名 `G<id>·<前两个代表动作>`。（规格中的导入脚本 `scripts/import_who_names.py` 尚未实现。）
6. **前缀覆盖**：IP 字典树上自底向上贪心，取覆盖 ≥ 90 % 成员、纯度（成员/区内活跃 IP）≥ 0.8 的最小 CIDR 集——“某几个 IP 段”，也是 IP 层次的 `reg` 级。

代价：签名每事件 O(1)；每日 MinHash O(n_IP·k)、LSH O(n_IP·b)、Louvain O(E log n)，E ≤ 10 n_IP。

#### 3.3.10 一致性检测：用最具体的已确认模式给每个事件打分（P03）

P03 在同拍 P04 之前运行，对**本拍每个事件**（不只是学习样本）用上一拍末的树与约束打分（前序；P03 从不写模型）。
覆盖节点 = 路由路径上最深的已确认/稳定/演化中/过期节点；IP 有例外时用例外节点；每种违规类型使用路径上“对该类型有足够支持（n_c ≥ 20）的最深节点”，
没有则 p = NaN（**从不写 1**）。

| 类型 | p 值 |
|---|---|
| 谁 | 节点的谁层级 ℓ* = 谁摘要**封闭**的最细 IP 层级：U_ℓ ≤ 0.05、重集合（按质量覆盖 ≥ 95 % 的最小条目集）≤ 8 项、证据跨 ≥ 5 个正常日。无封闭层级 → NaN（开放人群没有谁约束）。来源在重集合中 → 1，否则 `p_who = U_ℓ*`。标志：`outsider_group`（IP 有群组但该群组在节点上无质量）、`unknown_ip`（无群组、在该系统无历史）、`system_new`（其群组在整个系统无质量），以及绑定检查给出的 `readdress_candidate` / `concurrent_use` |
| 时间 | 该日类型密度下的最高密度区域 p（3.3.8） |
| 内容 | 数值（P06）、类别（层次 Dirichlet 的 HDR p）、集合（新键/缺必含键）、文本（语法/封闭集/长度）、绑定（p_bind、U_x）、不变式 `(n_viol + 0.5)/(n + 1)`、每 IP 强度；`p_content = min(1, m·min_a p_a)` |
| 序列 | p_seq（3.3.8） |
| 新动作 | 动作不在系统动作字典中：`p_novel` = 字典的未见质量 U；或落入已确认路由划分的 `other` 分支 |

每个 p_t 对当前约束与参考快照取 `min(1, 2·min(p_cur, p_ref))`；事件 p 值 `p_ev = min(1, 5·min_t p_t)`。
每个 (系统, IP) 每拍每类型按 Šidák 写检测器分数 `p_tick,t = 1 − (1 − min_e p_t(e))^{n_t}`，即 `behavior.score[conf_who|conf_when|conf_content|conf_seq|conf_novel]`，
进入 B24 校准 → B25 融合（族 `conformity`）→ B26 风险 → B27 事件单。离散的 `pattern_violation` 事件按“每 IP·每节点·每类型·每天”去重，
内容/时间/序列的阈值作用于**当天**的 `p_day = 1 − (1 − p_min)^{n_day}`——繁忙的 IP 不会因打分次数多而多得误报（每个干净 IP·日的期望机会发射 ≤ Σ 单元阈值，典型 ≤ 0.01）。
节点敏感度 `σ ∈ [1, 3] = 1 + [写方法] + 0.5·[ℓ* 上 ≤ 3 个 IP] + [路由匹配 sensitive_patterns]`。默认严重度（`progressive.md` §6.16.3）：

| 类型 | 条件 | 严重度 |
|---|---|---|
| 谁 | U ≤ 0.01、σ ≥ 2、`outsider_group` | HIGH 候选（B25 的佐证规则仍适用） |
| 谁 | U ≤ 0.02、σ ≥ 2、`outsider_group` 或 `unknown_ip` | MEDIUM；`readdress_candidate` 时 LOW |
| 谁 | U ≤ 0.05 | LOW |
| 绑定 | 认证路由上 `cross_binding` 且 LB ≥ 0.9 | MEDIUM；≥ 2 次为 HIGH 候选 |
| 绑定 | `concurrent_use` | MEDIUM；与谁违规同时出现为 HIGH 候选 |
| 内容 | 写动作上 p_day ≤ 1e-4，或 `injection_shape` | MEDIUM |
| 内容 / 时间 | p_day ≤ 1e-3（时间：且在所有窗外） | LOW；夜间写动作的时间违规 MEDIUM |
| 序列 | 缺少必需前置步骤 | LOW；写动作 MEDIUM |
| 新动作 | 系统级新动作且敏感或为写 | MEDIUM；否则 INFO |

**开放节点上的每 IP 强度**：谁不封闭时（大人群），按 IP 的滥用表现为强度。P03 对当前本地小时维护每系统一个 (ip, 节点) 对的 Space-Saving（k_int = 16 384，对少于此数的对精确），
只用**保证计数** `count − error` 与节点的 `rate.ip_h` 分布界比较（草图误差永远不会触发告警）；小时结束时把计数交给 P04 学习。
这样“任何 IP 都可以登录的门户上，某 IP 一小时 400 次登录”就成了内容（量、凭证）违规，而不需要随人群增长的按 IP 结构。

集成修订（M17、M20–M23，详见 `progressive.md` §16.2）：来源在覆盖节点上若自身已有 ≥ 3 个证据单位的“资历”，即使不在 95 % 重集合中也算成员（财务审批人只占财务系统证据的约 3 %，此前每次登录都被判违规）；
“同事”规则要求该群组在节点上有 ≥ 2 个**其他**成员具备资历（一个成员的个人习惯不是群组的模式）；来源在年轻的覆盖节点上陌生时，同时检验其已封闭的祖先直到系统根，
`p = min(U_node, n·min U_ancestor)`（Bonferroni），A1 因此从 LOW 变为检出。

#### 3.3.11 多侧面画像与两种视角（P13、P14）

**侧面注册表**（`lib/pfacets.py`；任何引擎可在运行时把侧面声明写入 `model.facets`，P13 无需改代码）。默认侧面树对应“看一个人”的各个维度：

|---|---|---|

| 2 时间节律 temporal | 作息 | 活动时间窗（P09）、周节律（B07）、自动化周期性（D0 periodicity） |
| 3 空间/网络 spatial | 住址与活动范围 | 来源 IP/网段/区域（P04 谁摘要、P11 覆盖）、目的地（B08）、跨系统足迹（P11） |
| 4 内容 content | 生物学特征（细节） | 大小区间与硬界（P06）、载荷语法与键集合（P07）、绑定（P08）、不变式（P05） |
| 5 序列/流程 sequential | 习惯动作 | 业务流程与必需前置步骤（P10） |
| 6 关系/社会 relational | 社会属性、常交往人群 | 行为群组与成员（P11）、关联/别名/共用 IP（B17） |
| 7 技术 technical | 常穿的衣服 | 客户端栈（R3）、TLS 特征（P02） |
| 8 量/预算 volume | 体型 | 流量规模（P12） |

| 10 风险/健康 risk | 健康记录 | 事件与违规（B27、P03）、画像策略与提示（P12） |

每个侧面有“适用”谓词（如内容侧面只在载荷可见的系统出现）；P13 为每个系统、质量最大的群组（`class:grp:<g>`，至多 256 个）与挣得的 IP 每 2 小时组装侧面树，其他 IP 在读取时组装（`profile.extra['facets']`）；B30 画像以引用（版本与侧面 id）方式内嵌它。
规格中由 B15/B16（身份）、B13（预算）、B10（个人动作语法）提供的子侧面尚未登记到默认侧面树。

**陈述对象**：`{pattern_id, view, subject, text_zh, text_en, support, confidence, first_seen, last_seen, version, state, facets, evidence}`。渲染规则：
谁——≤ 8 个 IP 覆盖 ≥ 95 % 且 U ≤ 0.05 时列出 IP；否则覆盖 ≥ 90 % 的群组给名称（≤ 5 个成员时列出）；否则 ≤ 4 个前缀/区域；否则“任意 IP（约 N 个，分散）”。
**置信度** = 陈述中各约束的最小值：谁 1 − U、时间窗 覆盖 × 日稳定度、区间 1 − |经验覆盖 − 名义| / 名义、语法 c_g·(1 − U_s)、绑定 LB_x、流程 依存度与边份额的 Jeffreys 5 % 分位；过期模式 × 0.5；候选模式默认不渲染。

**两种视角**（同一个模式库的两种投影）：
- **系统视角**（`model.pviews@(s, __system__)`）：系统 → 动作节点（按质量排序）→ 每个节点的谁、时间窗、内容约束、绑定、变体、例外 → 经过该节点的流程。
  M9：一个节点被 ≥ 2 个学到的群组共享（各占 ≥ 5 % 质量）时，另按群组分别陈述，每部分有自己的到达时间窗——这就是“OA 服务器的某类人会在哪个时间段访问我什么页面”；
  三个部门都阅读文档时 `GET /docs` 正确地是**一个**节点（没有目标随部门不同），只靠分裂永远命名不出“某类人”。
- **群组（用户）视角**（`model.pviews@(__org__, class:grp:<g>)`）：群组 → 成员/网段 → 该群组占其质量 ≥ 5 % 的系统 → 提升度 ≥ 1 或群组份额 ≥ 20 % 的动作 → 时间/内容/绑定（限于本组成员）→ 本组范围的流程 → **否定陈述**。
  否定陈述（M10：仅当系统中**没有任何**写节点有该群组质量时）如“综合部 在 finance 中从未执行写操作（14 天、0 次）”，正是让“综合部去财务系统审批”成为 who 违规的那条事实，分析员在它发生之前就能读到。

#### 3.3.12 场景自适应：系统刻画与策略选择（P12）

**刻画**（每系统每日）：用户规模（7 天去重 IP）、IP 流动性（每日新 IP 比例、短寿命 IP、DHCP 作用域、换址率）、IP 信息量（max_ℓ CR(net.src@ℓ)）、
源地址转换嫌疑、路由基数与增长（Heaps 指数）、载荷可见性（含 `http.*` / `body.*` 的事件比例、不透明 TLS 比例）、会话可识别性、量级、自动化比例、日历结构（月末、节假日质量）、系统族。

**策略维度**：谁的粒度（ip / grp / prefix / reg / none）、P07 语法与 P08 绑定（开/关）、P10 流程（开/关）、窗口树、节点档位（XS/S/M/L）、统计引擎的挣得上限与适用性（逐引擎 开 / 仅类 / 关）。
不满足前提条件的选项从不选（例如 ip 粒度要求 /32 上 CR ≥ 0.05、流动率 < 0.3/天且无源地址转换；P07/P08 要求载荷可见性 ≥ 0.05；P10 要求会话可识别性 ≥ 0.6 且路由数 ≥ 5）。

**谁层级的码长**（全信息度量）：每个谁摘要对每个学习事件的 IP 在每个层级累计两部码长

```
L_ℓ(ip) = −log2 p_ℓ(g) + log2 |g|          g = gen(ℓ, ip)，|g| = 该条目的地址空间大小（/32 为 1，/24 为 256，群组为其前缀覆盖的地址数，* 为 2^32）
未见条目：逃逸码 −log2 U_ℓ + 条目自身的地址比特
```

每个层级都是 IP 的完整编码，可以直接比较：DHCP 流动或大量随机人群下 /32 层不断为新 IP 付出逃逸 + 32 比特，网段、区域或 none 胜出；稳定部门则 /32 或 grp 胜出。

**效用与选择**：`U = 增益 − λ_c·成本`（比特/事件；增益为相对基线的前序增益，成本为实测 µs/事件，λ_c = 0.001 比特/µs）。可并行度量的维度用 Hedge（指数权重，η = 0.5/天，U 裁剪到 [−8, 8]），
必须实际运行才能度量的维度（P10）用预算 UCB；选中的选项按“收益/成本”贪心装入 P15 给出的 CPU/内存预算；切换需新选项连续 3 天高出 ≥ 0.05 比特/事件。

**系统族（服务器也不遍历）**：P12 每日对每个系统的路由前缀、主机、SNI、端口、主要客户端栈与注册属性名做加权 MinHash（k = 64），LSH 16 × 4 提议候选，
连续 2 天加权 Jaccard ≥ 0.6 且通道构成相容的系统组成一个族，共用**一棵**模式树、属性注册表与属性选择（树键 `fam:<id>`）。
服务器成为普通属性 `net.dst`（`peer:port` → 成员系统 → 站点/区域 → \*）：成员之间用户或动作不同时树会按 `net.dst` 分裂（因为划算），不同之处才单独描述——“一类服务器 → 某一台服务器”与“一类用户 → 某一个用户”对称。
新服务器的首日签名匹配到已知族后即用族的画像打分（冷启动）；与族的差异节点占族节点 ≥ 20 % 持续 7 天则脱离。

#### 3.3.13 资源治理（P15）

预算与节拍无关：P 内核 CPU 份额（默认 0.25 核，按小时平均）、内存总量（默认 2048 MB）、可选的按系统上限。每拍 P15 读取引擎耗时、P 内核模型大小（`lib/pnode.nbytes`、`psketch.nbytes`）
与 `store.memory_report()`（每 15 分钟），按 “P12 效用 × 关键度 × 近期学习事件速率” 注水式分配每棵树的节点档位、学习叶上限、e_rate、W_max、探针大小、各 LRU 上限、
暂存上限、P11 签名份额与统计引擎挣得上限；空闲 30 天的树写成检查点并移出内存。超预算连续 3 拍时沿**降级阶梯**每 3 拍走一步、24 小时内低于 70 % 预算后逆序恢复：
(1) e_rate 减半（只影响学习）→ (2) 停止探索 → (3) 学习叶减半 → (4) 降节点档位 → (5) 降统计引擎挣得上限（仅有界模式）→ (6) 解释/画像/侧面/视图改为读取时生成 →
(7) 最后手段：P00 跳过请求体解析，P03 在无谁约束、只读、非敏感的节点上按 1/k 抽样打分；写动作、敏感路由、谁封闭节点、新 IP 与被标记 IP 始终全量打分。
活跃集 `A_t(s)` = 本拍有观测的 IP ∪ 有打开事件 ∪ 被隔离 ∪ 累积器非零 ∪ 有暂存行的 IP；后四者由 B28、B13、B27 发布，从不扫描全部实体。

### 3.7 资源边界

**设计上界**（`progressive.md` §7）。每个事件的代价：

```
c_event = c_route·D + c_score·(m_t + 3)                                     每个事件（P03 打分）
        + π_e · [ c_upd·(2 + ρ̄(D − 2))·(m_t + 2) + 𝟙(学习叶)·c_split·C·(m_t + 2) + c_reg·A_ev + c_sig + c_dfg ]   学习样本（P04、P02、P11、P10）
```

与事件数（以及周期任务中新到的证据）成正比，从不与“IP 数 × 指标数”或服务器数成正比：打分项覆盖每个事件，学习项每树有 e_rate 上限，周期任务只处理脏节点，并受 A_max、R_p、S_max 约束。
每树内存 ≈ 节点数 × 每节点约 10 KB（估计）+ 学习叶分裂统计 + 绑定 + 注册表 + 探针 + 约束 + 各 LRU + 压缩后的保留事件批；各 LRU 上限按实际见到的来源数分配，不随人群无限增长。

| 主要上限（默认） | 值 | 作用 |
|---|---|---|
| 树深 D_max / 每节点目标 m_t / 每学习叶候选 C | 8 / 8 / 6 | 每事件更新次数有界 |
| 节点档位 N_max | XS 32、S 256、M 1024、L 4096 | 每树内存有界；空闲与新系统为 XS |
| 学习叶 L_max / 修订节点 R_max / 交替子树 | 64 / 16 / 4（M 档） | 最大的每节点块（分裂统计）有界 |
| 每系统属性 A_max / 每事件属性更新 A_ev / 窗口事件属性 A_win / 每小时轮转探测 A_probe | 512（XS 128）/ 32 / 96 / 64 | 指标再多，每事件、每小时的工作量也有界 |

### 3.9 统计引擎库（B01–B30）：定位、设计原则与算法详述

> 本节与 3.10 是统计引擎库 v2.1（第四轮评估时的代码）的完整描述。在 3.1 的新结构中，这些引擎是画像的侧面与检测器族，
> 决策链 B23–B30 由渐进内核共用；有界模式下逐 IP 模型只给挣得的 IP（3.5）。逐引擎英文规格见 `docs/lib3/engines.md`。

#### 3.9.0 定位、设计原则与分层

统计引擎库针对的是此前的需求表述（精确刻画某一 IP、泛化某一类、精准识别与日常画像不一致）。它把行为库做成
“每个业务系统 × 每个实体（IP）× 每个类”在运行中**动态生成**、可版本化的行为模型与画像集合——也就是逐实体建模；
大规模下这正是需求 S1 所禁止的遍历，因此在新结构中由渐进内核承担画像主体、由有界模式（3.5）限制逐实体模型。原需求与实现的对应：

| 需求 | 实现方式 | 主要引擎 |
|---|---|---|
| 为某一业务系统的某一 IP 精确刻画行为画像 | 每 IP 的精确预测分布（NB/Beta-Binomial/Student-t，按小时×日类型分桶）、节律、词表、动作语法、时序、客户端栈、预算；以自然单位出版可版本化画像 | B01、B03、B07–B13、B30 |
| 把某一类用户泛化为类画像 | 两级类层次（角色 → 个体子类）+ 静态 CIDR 类 + 地址池类；**类是一等实体**，有自己的聚合基线、检测器、事件、风险与画像 | B02、B18、B30 |
| 精度尽量细、且可区分 | 模板化动作令牌、客户端栈、亚拍时序、15 分钟 × 168 节律、对象级 HLL；在**绝对表示**上做分块交叉验证的可辨识度（EER）、易混淆列表、开放集归因与实体链接 | R2、R3、B11、B15–B17 |
| 当下行为与日常画像不一致时精准识别 | 暴露量精确的预测 p 值、双锚点基线、保形校准、调和平均 p 融合、按墙钟设定的误报预算、慢攻击累积器、变点检测、可回滚的治理 | B04–B14、B24–B28 |

1. **只经存储耦合**。引擎只通过 `MetricStore`（序列、float32 向量环、模型、事件、事件单、检查点、健康记录）交换数据；
   共享数学在纯函数模块 `backend/app/engines/behavior/lib/`（如 `features.py` 特征表、`detectors.py` 检测器注册表、
   `bayes.py` 预测分布、`combine.py` 融合、`calib.py`/`m_calib.py` 校准、`seq.py` 序贯阈值、`gating.py` 门控学习、
   `grains.py` 双粒度、`timebins.py` 时区与日历、`m_*.py` 模型访问器）。**没有任何行为引擎 import 另一个引擎模块**。
2. **时间是墙钟而非拍数**。半衰期、提交延迟、重拟合周期以秒计；每个序贯统计量的阈值由墙钟误报目标换算；
   严重度用 `e_day`（见 3.9.12）——“同样极端的空假设拍每实体每天期望出现几次”。
3. **缺失即数据**（见 §0）。`feature.active = 1` 当且仅当实体在 (now−Δt, now] 内有观测。
4. **晚学、只学可信数据、可逆地学**。学习器在 t 拍提交 t−D 行（D = max(4 拍, 600 s)），权重为该行的 trust；
   被隔离的实体只“挂起”不提交；学习器写几何间隔检查点，治理引擎可 `rollback_to` / `release` / `rebase_from`。
5. **分数先变成校准过的 p 值，再花预算做决定**。检测器写原始分数与驱动它的“轴”；B24 统一校准为随机化分层保形 p；
   B25 以加权调和平均融合并再校准；只有 B27 发通知。
6. **层次与“类即实体”**。估计沿 实体 → 角色类 → 系统 → 组织 → 超先验 逐级回退；每个类是伪实体 `class:<id>`。
7. **身份用绝对表示**。识别/归因/链接在每个候选者自己的模型下为窗口打分，从不使用对自身归一化的 `behavior.z`。
8. **一切可观测**。引擎错误、陈旧输入、降级检测器与校准漂移都会记录并通过 `/api/detectors/health` 暴露；
   测试与评估以 `ctx.config['strict'] = True` 运行，引擎异常直接抛出。

#### 3.9.1 特征表征（B01）

`FEATURE_SPEC v2`（`lib/features.py`）是 52 个命名特征、9 个组：
volume（bytes_up/down、flows、http_requests、dns_queries、tls_handshakes、intensity、bytes_per_flow、updown_log）、
breadth（distinct_peers、distinct_dports、distinct_templates、new_peer_count、dest_concentration）、
app（写/GET/4xx/5xx/3xx 比率、时延、请求/响应体、path_entropy、new_template_ratio）、
dns（名熵、DGA、失败率、TXT 比、qname 长度）、tls（SNI 熵、弱版本比、ja3_diversity、握手时延）、
timing（periodicity、timing_regularity、think_time、req_per_session、duty_cycle）、
transport（重传率、RTT、SYN 比、流时长）、probe（可达性、丢失率）、
comp（8 维组成 CLR：get、write、4xx、5xx、dns、tls、flows、syn）。

每个特征有“种类”决定变换与缺失规则：count/bytes 陈旧 → 0，否则 `log1p(v·60/Δt)`（每分钟速率）；
ratio 需新鲜的 k 与 n>0，否则 NaN；avg 需 n≥1；bounded 需 n≥5；window 当拍写出才有效；
`comp = CLR(x+0.5)`；`intensity = log1p(act.events·60/Δt)`。同时写暴露量 `feature.expo`
（http 请求、dns 查询、tls 握手、流、探测数）与时间上下文 `feature.tctx`（本地小时、星期、含节假日与调休的 day_type、
bin48/bin168、15 分钟槽、daypart ∈ {wd_day, wd_night, nwd_day, nwd_night}、节拍类 cc ∈ {60, 300, 900, 3600}）。

**80 维令牌草图**：5 个命名空间（act.tokens、client.stack_set、SNI eTLD+1、DNS eTLD+1、l4.dport_set）各 16 桶，
`v[ns·16+b] = Σ_{h(tok)=b} s(tok)·sqrt(c_tok / C_ns)`，非空块单位 L2 范数——用于身份表示。
标量 `feature.<name>` 是 `feature.vec` 列的虚拟视图，不复制。B01 不学习任何东西。

#### 3.9.2 节拍不变的双粒度特征（v2.1，`lib/grains.py`，默认 `grain_mode='canonical'`）

**问题**：v2 按“拍”定义特征。去重计数是次可加的（900 s 的每分钟速率约为 3600 s 的 4 倍），
突发量的对数速率有 Jensen 偏差，NB/BB 离散度随暴露量变化，身份窗口以拍计……
评估包在 3600 s 预热、900 s 评分，于是节拍切换本身就主导了误报（第一轮评估 A 包 1/12 威胁检出、校准偏离名义 ~500 倍）。

**做法**：每个被评分的特征都定义在**规范的墙钟尾随窗口**上：
H 粒度 G_h = 3600 s（主粒度，Δt ≤ 3600 可观测）与 Q 粒度 G_q = 900 s（灵敏度粒度，Δt ≤ 900 可观测），m = G_h/G_q = 4。
- **可加部件**：B01 每拍写 47 维 `feature.part`（Δt、活跃、字节、流、请求……以及“均值 × 权重”、“权重”对），
  窗口值是窗口内部件之和的函数，对任何 Δt ≤ G 精确。
- **集合特征**（distinct_peers/dports/templates、ja3_diversity）= 窗口内每拍 SetSketch 的并集基数（≤4096 精确，之后 HLL，误差 3.25%），
  需覆盖率 cov ≥ 0.95 G。**映射特征**（各熵、dest_concentration）合并窗口内的计数映射后再按 D1 规则计算。
- **跨度特征**（periodicity、timing_regularity 为 6 h；req_per_session、duty_cycle 为 24 h，按本地时间对齐）只在各自跨度的决策拍评分。
- **决策拍**：`decision(now, Δt, G) = ⌊(now+ε)/G⌋ > ⌊(now−Δt+ε)/G⌋`，按纪元对齐、所有实体相同（B05/B18 需要同拍的成员行）。
  滚动行 `feature.live.<g>` 每拍写（用于展示），被学习与评分的行 `feature.{nat,vec,meta,expo}.<g>` 只在决策拍写，相邻两行不重叠——
  否则 60 s 节拍会把同一小时学 60 次、序贯图重复计数。
- **行的时间上下文取窗口中点**：`row_tctx(now, g) = tctx(now − G_g/2)`（v2 以拍末时间分桶，3600 s 行晚半小时）。
- **拍类型** τ ∈ {h, q, t}：H 决策拍为 h，否则 Q 决策拍为 q，否则 t。每天决策拍数
  `n_h = 86400/max(3600, Δt)`，`n_q = 86400/900 − n_h`（Q 可观测时），`n_t = 86400/Δt − n_h − n_q`。
- **tick 模式**（`grain_mode='tick'`）是退化配置 G_h := Δt、无 Q，逐位复现 v2（`tests/test_tick_mode_golden.py`）；
  引擎/库/核心单元测试在 tick 模式运行，流水线、Runtime、评估与脚本默认规范模式。

#### 3.9.3 多分辨率基线（B03）

- **超先验**（`lib/priors.py`）：count 为 Gamma-Poisson（μ0 = 1 次/分钟，形状 0.5），ratio 为 Beta(0.5, 0.5)，
  其余为 NIG（κ0 = 0.01, α0 = 1, β0 = 4）——第一拍就给出有限、宽的预测分布，冷启动不会死锁。
- **分桶**：bin48（工作日/非工作日 × 24 h），满 4 周后 bin168；每次提交以 von Mises 权重
  `exp(4(cos(2π·Δh/24) − 1))`（|Δh| ≤ 2）扩散到相邻小时。
- **充分统计量**（以 γ = 2^(−Δt/H) 衰减）：count 为 [W, Σx, Σe, Σx², Σxe, Σe²]（e 为暴露分钟数），
  ratio 为 [W, Σk, Σn, Σk²/n, Σ(k/n)²]，其余为变换值上的 NIG。半衰期 H 每 96 次提交按 p5/p95 的 pinball 损失在 {7, 14, 28} 天中选择。
- **层次回退**：实体 → 角色类（系统内 ≥3 成员）→ 系统 → 组织 → 超先验；回退伪计数按经验贝叶斯
  `κ = m(1−m)/var_between − 1`，裁剪到 [2, 50]。
- **双锚点防投毒**：**当前锚点**每个桶均值每天最多移动 0.1σ15（σ15 为 15 分钟暴露的预测标准差，因此与节拍无关）；
  **参考锚点**延迟 24 h、只收 trust = 1 且 ±24 h 内无事件/无状态变化的行，每天最多 0.03σ15，有“黄金”快照（低风险周的 4 周中位数）后以黄金为准。
- **门控提交**（`lib/gating.py`）：提交 t−D 行，权重 trust(t−D)；H 行的权重取窗口内**最小** trust（含任一不可信分钟的小时不算干净小时）；
  隔离时挂起；每小时写检查点（1、2、4、…、168 h 几何保留）；遵从 `model.control` 的 rollback_to / release / rebase_from / frozen / allow_drift。
- **Q 粒度（v2.1）**：H 有完整双锚点；Q 有原生的当前锚点。Q 预测分布 = Q 原生统计 ⊕ κ_T = 16 条“转移伪行”：
  由 H 预测分布按方差尺度因子转移
  `v_f = 1 + ((m−1)/m)·ω_f`，
  NB：`μ_T = μ_H, r_T = r_H / v_f`；BB：`p_T = p_H, c_T = max(5, (1+c_H)/v_f − 1)`；
  t：`loc_T = loc_H + δ_f, scale_T = scale_H·√v_f`（对数量默认 `δ_f = −(v_f−1)σ²_H/2`，即对数正态恒等式）。
  ω_f 是“小时内四个刻值的超额方差 / 小时粒度超额方差”，在**成对小时**（一个 H 行恰含 4 个 Q 行）上估计，
  并沿 实体 → 类 → 系统 → 组织 以 24 个伪成对小时做 EB 收缩；无成对小时时默认 ω = m（v = 4，即独立刻的保守上界，对纯 Poisson 精确）。
  可交换刻假设下该分解是精确的（模拟：真值 4.005/1.694/1.097/1.000 被复现到 4 位有效数字）。
  原生权重占比 `π_nat = W_native/(W_native + κ_T)` 的中位数 < 0.5 时，该拍 Q 分数标为 provisional。
  Q 的“参考”预测分布恒为 H 参考锚点的转移，使 Q 同样有双锚点防蠕变保护。

#### 3.9.4 精确预测分布与边际检验（B04）

对每个活跃行、每个特征，在其桶的预测分布下计算**双侧 mid-p**：
- count：负二项 `NB(mean μ̂·e, size r)`，`r = 1/(1/κ̂ + 1/a)`（κ̂ 为矩估计超离散度，裁剪 [0.5, 1e3]；a 为后验形状），
  CDF 用 `betainc` 精确计算；
- ratio：Beta-Binomial `BB(n*, p̂c, (1−p̂)c)`，`c = min(Σn+2, φ̂)`，φ̂ ∈ [20, 1000]；n* ≤ 200 精确，n* = 0 为 NaN；
- 其余：NIG 后验预测 Student-t。

**双锚点合并**：`p_f = min(1, 2·min(p_cur, p_ref))`；`z = Φ⁻¹(u_cur)`、`zr = Φ⁻¹(u_ref)`（B05/B06/B14 使用）。
**通道**：先在 B06 学到的依赖组内做加权 HMP（权重 1/|组|），再跨组 HMP——volume 组得 `marg_int = −log10 p`，其余组得 `marg_shape`，
在类桶预测分布下同样计算得 `peer`；p < 0.01 的组写入 `behavior.axes`。
模型 p 值写入 `behavior.pm` 作为校准的小样本先验；`profile.extra.model_state` 给出每粒度 p5/p50/p95（自然单位：每小时 / 每 15 分钟）。
规范模式下 H 行出 `marg_int/marg_shape/peer`，Q 行出 `marg_int_q/marg_shape_q`（无 peer_q）。
性能：一拍所有行批量组装预测分布（`m_baseline.predictive_set_many` / `predictive_q_many` / `quantiles_many`），NB mid-p 数组化；
BB 保持标量路径以保证逐位一致。

#### 3.9.5 共模剔除与多元检测（B05、B06）

**B05 共模（留一法）**：只对 volume、transport、app-error、probe 组剔除组织/系统/类共同移动：
`L^{(−e)}_{t,g} = median_{其他≥3个活跃未隔离成员} mean_{f∈g} z`；载荷 `β = (ΣLz + 4)/(ΣL² + 4)`（向 1 岭收缩）；
`zi = z − β·L`。当实体本拍有系统级新颖、库四 ≥ medium 命中、客户端/身份 p<0.01 或外发预算证据时**不剔除**，
防止协同攻击借共模“洗白”；categorical/identity/c2/exfil 证据永不被共模影响。

**B06 多元**：在门控提交的 zi 行（≤336 行）上：Winsorize ±4 → OAS → 一步 C-step（保留 d² 最小 75%，按 χ² 中位数重标定、χ²_{0.975} 重加权）→ 再 OAS；
特征值下限 1e-3·均值；年轻实体向类协方差收缩 `Σ̃ = (nΣ_e + 30Σ_class)/(n+30)`。
- **Hotelling T²**（量级）：在观测维 o 上 `T² = z_oᵀΣ_oo⁻¹z_o`，按预测分布缩放
  `T²·n(n−q)/(q(n−1)(n+1)) ~ F(q, n−q)`；
- **SPE**（相关性破坏）：缺失维用条件期望 `z_m = Σ_moΣ_oo⁻¹z_o` 补全后 `SPE = ‖z − U_kU_kᵀz‖²`，p 值用 Box 近似 g·χ²_h；
- **RBC 贡献** `RBC_f = (e_fᵀΣ⁻¹z)²/(e_fᵀΣ⁻¹e_f)`（各为 χ²₁），给出轴与解释；每 32 拍/8 h 以 |Spearman ρ| > 0.8 平均链接更新依赖组 `model.groups`。
规范模式下 H、Q 各一套（Q 密度向 H 收缩，n_Q < 64 时 provisional）。

#### 3.9.6 时间、节律、时序与信标（B07、B11、B12）

**B07 节律**（固定 15 分钟槽时钟，与节拍无关）：`P(active | bin) ~ Beta`，按 bin48/bin168、von Mises 平滑、类先验 Beta(6π, 6(1−π))、28 天遗忘。
- **非工作时间**：仅在 p̂ ≤ 0.3 的桶上跑伯努利 CUSUM（单位 bit），`p1 = min(0.95, max(0.5, 5p̂))`，
  `W ← max(0, W + a·log2(p1/p̂) + (1−a)·log2((1−p1)/(1−p̂)))`，阈值 `h = log2(ARL_slots) + 0.5`（ARL = 100 天，h ≈ 13.7 bit）；
  p̂ = 0.02 时每个活跃槽 +4.64 bit，第 3 个活跃槽告警；`p_eq = 2^(−W)`。
- **静默**：仅对“机器型”实体、p̂ ≥ 0.95 的桶，`s = Σ −ln(1 − p̂_b)`，`p_eq = e^(−s)`。机器型由**自动化指数**判定
  （`m_rhythm.automation_index` = 非工作时间活动比、非工作日/工作日比、出现规律度 `1 − Σr·4r(1−r)/Σr`、B02 的每 IP 自动化指数 A 四者均值，
  进入 0.6 / 退出 0.4 的迟滞，规律度 < 0.5 时绝不判机器型）。在生成器 37 个画像 × 2 种子上：人 0.14–0.33，机器 0.73–0.93（旧的熵规则把 22/36 的人判成机器）。
- **作息平移**：常规窗口静默后 24 h 内在新窗口出现同时长同量活动 → `schedule_shift`(LOW)，其时间证据封顶 LOW；目的地/内容变化不封顶。
- 日历自愈：某桶全系统出现率超常 3 倍时按工作日处理。

**B11 时序**：动作流时间戳上 10 ms–1 天的 32 桶对数间隔直方图（τ = 7 天），`score.timing` = 近 6 h 直方图对其 JSD（累积型，轴 temporal）；
突发度 `B = (σ−μ)/(σ+μ)`、记忆 `M = corr(Δ_i, Δ_{i+1})`、思考时间对数正态拟合、5 s 分箱 rfft + Rayleigh 确认的严格周期；
描述量写 `behavior.timing` 供身份与画像使用。

**B12 信标**（按 (实体, 稀有目的地)，只看流行度 ≤ 20% 且非类共享的目的地）：
1. **Gamma 更新过程正则性检验**（主检验）：MLE 拟合间隔的形状 κ̂，`LR = 2[ℓ(κ̂) − ℓ(1)]`（κ̂ > 1 单侧），
   p 值来自按 n 预计算的**有限样本蒙特卡洛零分布表**（χ²₁ 渐近在 n ≤ 40 时反保守 2–5 倍），复合零假设取最不利 κ0 = 1.5；
   ±30% 抖动、周期 300 s 时 n = 12 的中位 p = 1.7e-8。
2. 字节大小恒定性（目的地类内的秩检验）；3. 低抖动时的 Z²₂ 严格周期检验（过采样试探周期网格 + 有效试验数校正）。
合并 `p = min(3·min(p_renewal, p_size, p_Z²), 1)`；p < 1e-5、目的地流行度 ≤ 2 个实体、且类内不共享 (目的地, 周期 ±10%) 时告警。

#### 3.9.7 类别新颖、客户端与动作语法（B08、B09、B10）

**B08 新颖**（维度：方法+模板、内容类型、SNI/DNS eTLD+1、qtype、端口、对端 /24、库四类别）。分层 Dirichlet 回退：
`p_e(v) = (c_e + 5p_c)/(N_e + 5)`，`p_c(v) = (c_c + 5p_s)/(N_c + 5)`，`p_s(v) = (c_s + U)/(N_s + 1)`，惊异 `I_v = −log2 p_e(v)`。
- Good–Turing 新颖率检验：`p_new = (N1 + 0.5)/(N + 1)`，n 次访问中 k 个首见的 p = `betainc(k, n−k+1, p_new)`；
- 类稀有度 IDF × 敏感度权重 w ∈ [1, 3]；`score.novelty = max(−log10 p_rate, ω·Σw·I/12)`（瞬时）；
- `novelty_rate`（每日类稀有新值计数的 NB 检验，累积）、`jsd`（1 h/24 h 窗口分布对画像的 JSD，累积）；
- 轴：默认 categorical；外部且上传主导 → exfil；敏感/管理 → privilege。
- **采用折扣**：7 天内 ≥ max(3, 30%) 类成员首见同一值时，个体分数 ×0.1 并发 `class_adopted`，但采用记录（外部/上传/敏感/新 eTLD+1 标志）
  **总会**写入 `model.vocab@class` 交给 B18 评分——个体折扣无法掩盖有风险的全类采用。

**B09 客户端栈**：栈令牌的分层 Dirichlet（14 天半衰期）；并发 C（主栈与新栈的事件区间重叠或相距 < 5 分钟，与节拍无关）、
替换、不一致 I（UA 声明的 OS 与 TTL 类不符或 `p(ja3n | UA 族) < 0.01`）、推广 R（7 天内类中获得新栈的比例）；
`risk = σ(0.6S + 3C + 2I − 4R − 3)`，`score.client = −log10(1 − risk + 1e-6)`；C 或 I 且 risk > 0.8 → `client_impersonation`(HIGH)。

**B10 动作语法**：动作流令牌（系统计数 < 3 映射为 `{rare:<channel>}`）上的 **PPM-C（阶 ≤ 3，30 天衰减）**，
逃逸时回退到以稳定 id 为键的角色类 PPM，再到系统一元（Good–Turing 新质量）；会话间隔阈值取对数间隔直方图谷值（2 分钟–2 小时）。
分数：窗口超额 `E = mean_{W=8} surprisal − Ĥ_e`（相对实体自身熵率）、会话 NLL 收缩、会话内 CUSUM（h = 8 bit）、
半马尔可夫驻留 `dwell = −log10 P(L ≥ ℓ)`、`class_llr = log P_e − log P_class`；认证族令牌的轴为 credential。
类/系统层的 PPM 在成员状态未变时复用（`test_b10_tier_reuse`）。

#### 3.9.8 累积预算与变点（B13、B14）

**B13 预算**（DLP 式长时累积，按轴拆分）：volume（上/下行字节、写请求、活跃槽）、exfil（发往 7 天内新或类稀有目的地的上行字节、
新 eTLD+1 的 DNS 标签字节）、breadth（每模板去重对象 ID（HLL）、去重模板、去重目的地）。
28 天 × 24 小时环，视界 1 h、8 h、同相位同日类型的当日累计、7 d；阈值为 POT/GPD（u = 同相位历史 P98，PWM 估计），
评估分位 `q = 0.01/(#Q·#H·24)` 使族误报 ≤ 0.01/实体·天；历史 < 20 天用同伴池化 GPD；
告警还需超出绝对下限（`budget_abs_floor`）并通过同伴中位数守卫（外发不适用）。计数量的对数尺度下限覆盖其计数噪声
`sqrt(m+1)/(m+1+unit)`（第二轮修复：常数历史的计数相位不再产生 1e-10 级假尾部）。

**B14 变点**（输入为对**参考锚点**的残差 zr，12 个关键特征，AR(1) 预白化 `u = (zr_t − φzr_{t−1})/sqrt(1−φ²)`，截断 ±3；
只用实体**自有支持**的特征，`m_baseline.own_support`）：
- **CUSUM 组**：12 特征 × 2 侧 × k ∈ {0.25, 1.0} = 48 张图，族目标 0.02/实体·天 → 每图 ARL 2400 天，
  Siegmund 阈值 `h = seq.h_gauss(k, ARL)`；规范模式按小时决策行抽样（非重叠），ARL 以小时计，**h = 16.60（k = 0.25）在任何节拍下相同**
  （v2 为 900 s 19.37、60 s 24.79）；`p_eq = min(1, 48·exp(−2k(S + 0.583)))`；轮询自举审计超额时把 h 放大至多 1.5 倍。
- **Crosier MCUSUM**（`Σ^(−1/2)zr`，k = 0.5，ARL 100 天，h = 22.72）；**BOCPD**（小时尺度，Normal-Gamma，危险率 1/168 h，
  cp.prob = P(r ≤ 3 h)，起点 = MAP 游程起点）；**蠕变**（14 个日值的 Mann–Kendall，p < 0.01 且 |Sen 斜率| > 0.05 对数单位/天 → `baseline_creep`）。
- 估计起点 τ̂ 写入 `behavior.cp.onset` 供回滚；CUSUM 状态向量存档供 B29 精确重放。
- 规范模式下 H 拍之间保持（重报）已锁存的告警；预热结束后的**第一拍（不论类型）**重启图表（第三轮修复）。

#### 3.9.9 身份、归因与实体链接（B15、B16、B17）

**窗口**（v2.1）：4 个**活跃 H 行**（任何节拍下都是 4 小时墙钟数据）。窗口向量是**绝对表示**：
H 行 `feature.vec.h` 中位数（NaN 用角色类桶中位数替代并附缺失掩码）、8 个关键特征的 IQR、平均 80 维草图（客户端栈块置零）、
时序描述量（B, M, 思考时间）、本地小时 sin/cos 与工作日标志；系统内 PCA 到 48 维。

**B15 身份模型**（每 96 拍或 24 h）：OAS 池化类内协方差 + 角色内 WCCN + 收缩 LDA；**分块交叉验证**（每实体 3 段连续折、间隔 2 窗口）：
recall@1/@K、`EER_hard`（对 Bhattacharyya 距离最近的 3 个冒充者）、T99、混淆行、并查集匿名集；`separability = clip(1 − 2·EER_hard, 0, 1)`；
为每种模态 m ∈ {gauss, vocab, rhythm, seq, client, timing} 用逻辑回归拟合 LLR 校准 (a_m, b_m)；Fisher 分数与 Monroe–Colaresi–Quinn 对数几率给出“区分性特质”。

**B16 开放集归因**：候选 = 自身、LDA 空间前 5、自身角色类、次优角色；每种模态在**候选者自己的模型**下算对数似然
（LDA 高斯块、Dirichlet 平滑词表多项式、节律、`ppm.loglik`、客户端栈、间隔直方图），`a_m·llr + b_m` 并截断 ±4 nat（浏览器升级无法单独翻转身份），
加入先验 0.05 的“未知”假设求后验。
- `score.identity` = 自身后验 LLR 尾部的 −log10（B24 按 (daypart, 状态三分位, cc) 分层校准；因窗口重叠只走单拍路径，不进证据 CUSUM）；
- 他人身份 CUSUM：`λ = clip(max_{j≠e} l_j − l_e, −4, 8)`，`S = max(0, S + λ − 0.5)`，只在**不重叠**窗口上步进，h 由 ARL 100 天换算；
  满足且同一 j* 在 4 个窗口中赢 ≥ 3 次、π_j* ≥ 0.9、交叉验证混淆 < 0.1 → `identity_mismatch`（j* 同时在别处活跃时为 HIGH）；
- 未知 CUSUM（仅完整 K 行窗口上升）：类典型性 p < 0.01 → HIGH“谁都不像”；否则 MEDIUM“同类但非已知个体”。
  典型性距离先按候选者留出真窗口的 T99 标定再过 χ² 尾部。

**B17 实体链接**（DHCP/VPN 换址、IP 跳变）：新实体 B 出现后前 8 个活跃拍内，对同池/同 DHCP 范围且此后不再活跃的 A 计算 Fellegi–Sunter 对数几率
`LO = 行为 LLR + 词表 LLR + 设备 LLR + 拓扑先验(同 /24 +2，否则 −2) + 时间先验(按租期指数)`，匈牙利一对一分配；
LO ≥ 5 且领先次优 ≥ 2 → 链接（`model.link` 版本 +1，学习器执行种子 `B := B_own + 0.5·A`）；行为吻合但设备 LR ≤ 0.1 → `possible_impersonation`；
A 复活则撤销链接（B28 回滚到链接时刻并释放）。共享 IP：最近 96 个活跃 zi 上 k=1/2 高斯混合，BIC 差 > 10 连续 3 次且两套不相交客户端栈时间重叠 → `shared_ip`。
24 h 内的链接串成 `model.link.actors`（B13 按 actor 聚合预算）。

#### 3.9.10 类即实体（B02、B18）

**B02 两级类层次**（每 16 拍或 6 h 重拟合；冷启动路径每拍）：
- 角色描述子（与个体无关）：自动化指数 A、通道组成 CLR、模板族分布、48 桶节律形状、量级、设备类；
  `D_role = 0.3|ΔA| + 0.2·Aitchison/norm + 0.2·√JSD(族) + 0.2·(1 − cos 节律) + 0.1·[设备类不同]`；
- 第一级：组织内池化的 HDBSCAN（precomputed，min_cluster_size = 2，eom），噪声为 `unique` 单例，噪声 > 30% 时回退平均链接凝聚聚类；
  超层：人/机（A 的 0.4/0.6 迟滞）；
- 第二级（角色内个体子类）：`D_ind = 0.4·mean_f W1(预测分位) + 0.3·√JSD(模板/SNI/端口) + 0.2·(1 − cos 节律168) + 0.1·[栈不同]`，HDBSCAN leaf；
- 稳定 id：对成员 Jaccard 做匈牙利匹配（J ≥ 0.3 继承），分裂/合并事件，3 次缺席退休；软隶属 `P(c|e) ∝ exp(−D_role/d90_c)`；
- 静态 CIDR 类（`ctx.config.ip_classes`）与地址池类（≥5 个同角色短寿命 IP）；新实体冷启动归类 `new_entity_matched`/`new_entity_unmatched`。

**B18 类监测**：对每个角色类（≥2 成员）、静态类（≥3）、池类构建每拍聚合行（成员计数与暴露之和、池化比率 Σk/Σn、活跃成员比例、令牌并集、
新外部目的地数），用与 B03 相同的共轭季节模型 `model.classagg`（双锚点、类 trust 门控，规范模式从 `behavior.class.agg.h` 学习）。
检测器：`class_int`（量级）、`class_shape`（组成与模板 JSD）、`class_rhythm`（每 15 分钟槽活跃成员数的 Beta-Binomial CUSUM）、
`class_novel`（≥2 成员 24 h 内采用的新值：`Σ w_v·(−log10 P(M ≥ m_v | 历史采用率))`，外部 ×3、上传主导再 ×3、敏感再 ×3、全组织新 eTLD+1 ×2，内部只读模板 0.1）、
`class_coherence`（同组同向偏离成员数的二项尾部）。
解读规则：一致的纯量级变化（如月末 L1）与全系统应用错误/传输变化（L10）封顶 LOW；有风险的采用（T21 被控地址池）按 p 值分级。
第三轮修复（规范模式）：成员在某槽是否活跃取自 `act.slot_events`（不再用“该拍任意时刻活跃”），每个完整槽按时间顺序评分与学习；
某槽只在其自身 bin 已有 ≥ 3 个衰减槽（`RHYTHM_MIN_BIN_W`）时才评分。

#### 3.9.11 保形校准（B24，全部检测器 p 值的唯一所有者）

对每个 (实体或类键, 检测器, 层) 维护最多 256 个分数的有序环，只收门控提交的可信行（成熟度 n_eff ≥ 48、未隔离）；
回滚点之后的条目删除，版本变更时重置。
- **随机化保形 p**：`p = (#{c > s} + U·(#{c = s} + 1)) / (|C| + 1)`，U ~ U(0,1) 由 hash(s, e, d, ts) 播种（可复现）——消除稀疏/累积检测器在 p = 1 的点质量。
- **分层**：T 流为 (daypart, cc)；规范模式 H 流 (daypart, 'h')、Q 流 (daypart, 'q', prov)、身份 (daypart, 三分位, 'h')。
  H 环每天 24 条、跨节拍切换延续，不再因切换清空。
- **GPD 尾部**：s 超过环的 0.90 分位 u 且超出点 ≥ 10 时，`p = (N_u/N)(1 + ξ(s − u)/σ)^(−1/ξ)`（PWM，ξ ∈ [−0.5, 0.5]）。
- **小样本（|C| < 64）**：先用同节拍其他 daypart 的自身环（≥64），再用模型 pm 先验，再用类池化环，权重 n/(n+64)；
  **pm 先验**（`m_calib.pm_prior`）对 pm 的两个原子做 mid-p 随机化：pm = 1 → `1 − π1 + u·π1`，pm 处于浮点下限 → `u·π0`，
  π 为该原子在实体已收 pm 历史（环 `<d>@pm|<cc>`，H/Q 为 `<d>@pm|g:<g>`）中的占比；
  **自身历史下限**：先验可以在环外增加分辨率但不得与之矛盾，`p ≥ #{ring > s}/(n+1)`（第二轮修复，稀疏的夜间备份主机不再每晚 p≈1e-16）。
- **健康**：每检测器每系统在可信拍上的 KS D 与 e_day ≤ 0.03 的实际超越率；KS D > 0.05 或率比超出 [0.5, 2] 时 `weight_mult = 0.5`。
  输入 NaN → 输出 NaN。实时提交再以治理引擎的行证据权重 `m_governor.evidence_weight` 封顶（只对被释放的挂起行生效）。

#### 3.9.12 融合、单拍预算与证据 CUSUM（B25）

1. **加权调和平均 p（wHMP）**：`p_family = Σw / Σ(w/p_d)`（排除 NaN；族无有效输入则标记降级），
   `p_inst` = 含瞬时检测器的族上的 wHMP（只用瞬时成员），`p_all` = 全部族上的 wHMP；族权重 = 反馈 family_w × 校准健康 weight_mult。
   选 HMP 而非 ACAT 的原因：`ACAT([1e-3, 0.999, 0.5]) = 0.5` 会被一个接近 1 的 p 掩盖，而 HMP 为 0.003；ρ = 0.64 等相关下 HMP 在 1e-3 处为名义的 1.095 倍。
2. **元校准**：每实体的 `−log10 p_inst`、`−log10 p_all` 环（按 (daypart, τ[, cc]) 分层，随机化，GPD 尾部）给出 `q_inst`、`q_all`。
   尾部拟合前把超出“n_u 个指数超额最大值的 99.9% 界”的点替换为其期望次序统计量（`calib.winsorise_exceedances`，α = 0.001）——
   有效 p 的 −log10 为指数尾，更重的拟合尾部只能来自污染（预热期的极端 p_all 曾把 q_all 压在 5e-4 附近）。
3. **单拍预算（按拍类型分摊）**：
   `e_day = q_all · n_τ / β_τ`，β = (h 0.5, q 0.25, t 0.25)，在存在的类型上重归一化——
   每实体·天总的空假设单拍告警期望恒为 0.03；Δt = 3600 时退化为 v2 的 `q·86400/Δt`；
   900 s 下 H 拍门槛 q ≤ 8.3e-4、Q 拍 ≤ 1.4e-4；60 s 下 H/Q/T 为 6.3e-4 / 1.0e-4 / 5.6e-6（v2 为每拍 2.1e-5，小时级证据贵 60 倍）。
4. **证据 CUSUM（按流）**：`S = max(0, S − ln q − 3)`，`h = (ln ARL − 3.07)/0.94`（ARL ≈ 21.6·e^{0.94h} 由积分方程精确求得）。
   S_t（T 流瞬时检测器：novelty、client、seq、dwell）每拍更新；S_h（H 流瞬时检测器，**不含**重叠的 identity）每小时更新；
   两者各占一半预算（ARL 66 天），H 流在任何节拍下 h = 4.57，T 流 900 s 为 6.05、60 s 为 8.93。Q 流嵌套在同小时 H 窗口内，**不进** CUSUM。
   按流的块自举审计超额时把 h 提高至多 20%。
5. **路径与严重度**：单拍 `e_day ≤ 0.03·alpha_mult`、证据告警、任一累积器 `acc_alarm`（其 e_day = `min_d p_d·86400/period_s(d)`）。
   e_day ≤ 0.03 LOW，≤ 3e-3 MEDIUM，≤ 3e-4 HIGH 候选，≤ 3e-6 CRITICAL 候选；
   HIGH 需佐证（按流墙钟窗口内 ≥2 个轴族 e_day ≤ 0.03，或同流连续 2 个决策拍 ≤ 3e-3，或离散发现 ≥ HIGH）；CRITICAL 需 ≥3 个轴或库四 ≥ high；
   provisional 的 Q 证据权重 ×0.5、最多到 MEDIUM、不计入 HIGH/CRITICAL 佐证。
6. **按轴的解读规则**：纯 volume 证据实体封顶 MEDIUM、类封顶 LOW；自身/同伴 2×2（自身异常同伴正常降一级，两者都异常升一级）；
   共模标志只降 volume/transport/app-error 一级；作息平移解释的时间证据封顶 LOW；系统内每拍对 LOW 单拍路径做 BH(q = 0.05)。

#### 3.9.13 风险与事件（B26、B27）

**B26 风险**（0–100，可解释、衰减、与节拍无关、不可被投毒）：
- 连续证据为“超出每日期望的惊异”：`b_f = W_f·max(0, log10(1/e_day(p_family)))`，W：identity/c2/exfil 2，shape/categorical/breadth/change/sequence 1.5，其余 1；
  同一 (实体, 族) 在一个事件/片段内第 n 个连续拍 ×0.5^((n−1)/4) 饱和；
- 离散事件（系统级首见 15、类级 8、实体级 3；rare_access、各类冒充、new_entity_unmatched、beacon、budget_exceeded、class_adoption_risky 等 15–20），24 h 内重复 ×0.5^(n−1)；
- 库四命中（info 0, low 5, medium 15, high 30, critical 50，× 置信度），**习惯性**的 ≤ medium 命中（同 (实体, 特征) ≥ 4 拍且首次 ≥ 24 h 前）权重 0；
- 按墙钟半衰期衰减（行为 12 h，变化/序列 24 h，新颖/身份 72 h，c2/外发/critical 48 h），杀伤链阶段乘子 `M = min(2.2, 1 + 0.3(#阶段 − 1))`：
  `risk = 100·(1 − exp(−M·c_s·π·ΣL / L_ref))`，**L_ref = 60 固定**（离线确定，从不由实时数据设定；空假设模拟 L 均值 ≈ 7、p99.99 ≈ 17–19 → risk ≤ 27）。
  类风险 = max(类伪实体自身风险, 前 3 成员均值)。分层 Low < 30 ≤ Medium < 60 ≤ High < 85 ≤ Critical，迟滞 10。

**B27 事件**（唯一通知者）：
- 打开：任一告警路径；离散发现 ≥ MEDIUM；类告警；或 risk ≥ Medium 持续 ≥2 拍且 24 h 内有族 e_day ≤ 0.1、该族命中新于上次事件活动、
  并且**新增风险** `100(1 − e^{−(x_now − x_old)}) ≥ 30`（x_old 为上次事件活动时的风险按最慢半衰期 72 h 衰减；第三轮修复，A 包重开次数减半）。
- 合并：同实体/链接别名/actor 在 max(4 拍, 1 h) 内并入；严重度上升或新轴 → 升级。
- **关闭与风险无关**：治理 RETURNED / ACCEPTED、标签关闭、或 max(8 拍, 2 h) 无告警无发现且所有累积器 < h/4 且最近 4 行 e_day(q_inst) ≥ 1；
  挂起 > 14 天送标签队列而非自动关闭；24 h 内重开沿用 id。
- 共模父子（≥50% 类成员同拍只在 volume/transport/app-error 轴告警 → 成员事件挂到类事件下）、活动合并（同系统 1 h 内模式令牌 Jaccard ≥ 0.5）、
  反馈策略、令牌桶（每实体每小时 3、每系统每天 20）。

#### 3.9.14 治理与状态推理（B28）

- **信任**：`e_inst = min_s q_inst,s·N_s`；
  `trust_prov = clip(log10(e_inst/0.1), 0, 1) × [本拍无告警] × [无 ≥ MEDIUM 离散发现]`；
  `trust = trust_prov × [无打开事件] × [状态 ∈ {NORMAL, RETURNED}] × [所有累积器 < h/2]`；
  训练期 trust = 1（库四 ≥ HIGH 命中的拍除外）；`quarantine = 有打开事件 或 状态 ∈ {SUSPECT, DRIFTING}`；
  `trust_evidence`（仅实时拍，= 行自身的门：无告警 × 无 ≥MEDIUM 发现 × 累积器 < h/2）供 B24/B25 封顶释放行的入环权重。
- **状态机**：NORMAL → SUSPECT（累积器 ≥ h/2 且其 e_day·n ≤ 0.1、cp.prob > 0.7、蠕变或告警），τ̂ 早于提交前沿时写
  `rollback_to = τ̂ − Δt`（每小时至多一次、至多回溯 7 天、不回溯进预热行）；SUSPECT 持续 ≥1 h 且 ≥4 拍 → DRIFTING；
  所有累积器 < h/4 且 max(8 拍, 2 h) 无告警 → RETURNED（`release = [τ̂, t]`）。
- **合法 vs 攻击的对数几率**：按类型的先验（intensity 0、rhythm 0、ramp +0.5、shape −1、categorical −1.5、new_entity −1、identity −3、c2/exfil −4）
  加 ln LR 项：同伴一致 +2.08、库四 ≥ high −2.3、系统级敏感新颖或外部上传目的地 −1.6、身份自后验 ≥ 0.9 +0.69 / 身份不符 −2.3、
  变化后离散比 ≤ 1.5 +0.69、**在新状态中平稳且干净的时间**每 T_type/3 +ln 2（上限 ln 8；T_type：强度/斜坡/新实体 1 天、节律 3 天、形状/类别 7 天、身份永不累计）。
  例：单实体强度变化 0 + 0.69 + 0.69 + 2.08 = 3.46 → P = 0.97，1 天后 ACCEPT；形状 2.46 → 7 天；类别 1.96 → 需同伴一致或标签。
- **ACCEPT**（P ≥ 0.9、时长 ≥ T_type、无恶意类证据）→ `model.control{version+1, rebase_from = τ̂}`，学习器以 trust_prov 重放挂起行，关闭事件；
  **REJECT**（P ≤ 0.2 且片段有佐证：自身告警/累积器证据 ≥4 拍跨 ≥1 h，或两个独立恶意来源，或 tp 标签，`m_governor.reject_corroborated`）→ 保持隔离、丢弃挂起行；
  其余保持 DRIFTING(LOW)，14 天后进标签队列。不存在永久锁死。链接撤销由 B28 以 rollback + release 精确撤销种子。

#### 3.9.15 反馈闭环（B23）

从 `store.labels(since)` 读新标签：
- 每 (族, 贡献键) 精度 ~ Beta(1+TP, 1+FP)，风险乘子 `π = clip(E[prec]/0.5, 0.2, 2)`；
- ≥20 个已标事件后做向均匀 L2 惩罚（λ = 5）的堆叠逻辑回归得到 family_w（softplus 归一化），≥100 个标签后等渗校准 P(恶意)；
- fp / benign_known 且 scope = pattern 的标签生成**模式策略**（种类、前 5 (特征, 符号)、新类别令牌；允许级别为标签 e_day 的 1/10；TTL 14 天）；
  Jaccard ≥ 0.6 且在级别内的新事件以 `suppressed` 状态保存，仍以 0.25 计入风险；
- benign_known → 白名单（B08/B12 使用）；expected_change → accept、tp/malicious → freeze（B28 消费）；
- 每系统每日告警预算 `alpha_mult ← alpha_mult·exp(0.1(target − observed))`，裁剪 [0.25, 4]，只缩放 e_day 严重度门槛，不改校准；
- 标签队列每天 ≤ 5 条：80% 最高风险未标、20% 最不确定 |P − 0.5|，外加挂起 > 14 天者。

#### 3.9.16 忠实的反事实解释（B29）

对本拍打开或升级的事件：
1. 数值归因：用 `model_state` 给出自然单位与“本小时、本日类型的正常区间”（如“bytes_up 38.2 MB/15 分钟；通常周二 14:00 为 0.4–1.1 MB（35 倍）”），
   RBC χ²₁ p 值与 Garthwaite–Koch 份额 `c_i = w_i²/D²`（w = Σ^(−1/2)z），BH(q = 0.05)；在驱动检测器所在的粒度（H 或 Q）上归因。
2. 类别：新令牌（层级与首见时间）、消失的习惯令牌、客户端栈差异；序列：最不可能的 3 个转移。
3. **忠实反事实**（`lib/replay.py`）：贪心地把排名靠前的特征重置为桶中位数（或移除新令牌），**精确重算**所有受影响检测器——
   无状态检测器经纯函数对存档模型重算；有状态检测器（CUSUM 组、MCUSUM、节律 W、预算、身份 CUSUM、按流证据 CUSUM）从 τ̂ 起重放存档输入
   （规范模式重放至多 96 个 H 状态）；再经 `m_calib.p_replay`（含 pm 环）、wHMP、元校准、e_day 与决策规则。直到打开条件不再成立为止，
   报告最小集合、有效性（决策是否翻转）与范围（重算了哪些检测器与粒度）。
4. 同伴上下文、最近的已标模式、确定性的中英文模板（标题 + 3 条要点）写入 `incident.explanation` 与 narrative_zh/en。

### 3.12 放弃的方案与差异

#### 3.12.1 渐进画像内核（详见 `docs/lib3/progressive.md` §14）

- **每 (IP × 指标) 建模再汇总为类**（原统计引擎库的形态）：自底向上，先要为每个 IP 建模才能学到群组，代价 O(IP 数 × 指标数)；需求要求相反的顺序。
- **频繁项集 / FP-growth、对整个泛化格做形式概念分析**：项集/概念数随属性指数增长、支持度需要全量数据、没有内容模型。模式树是在同一个格上、有节点预算、由证据引导的贪心路径。
- **离线聚类全部事件**（k-means、HDBSCAN）：需要全量数据，混合类型，id 不稳定，不能增量更新。
- **只用 Hoeffding 界决定分裂**：增益范围约 25 比特时每次决定约需 10⁴ 个事件，每天登录一次的 3 人部门永远不会被细化；保留（经验 Bernstein、时间一致）作为候选之间的稳定性检验。
- **用累加的前序节省作显著性检验**（初稿）：在复合零假设下不是检验鞅、重复计算相关目标、多重性按评估次数而非候选计；改为按目标平均的 e 值（集成后为分块 e 过程，M2），累加节省保留为 MDL 收益与排序统计量。
- **形状与置信度用同一个指数衰减**：置信度会永远停在 rate × H/ln 2；改为带重置的置信通道。纯滑动窗口或只用 ADWIN 也放弃：它们遗忘稳定事实与遗忘已变化的事实一样快。
- **每台服务器一棵树、固定状态**：与服务器数线性增长，需求同样禁止；改为系统族、按活跃度分档、脏节点周期任务。
- **从流量学群组名称**：不可能——流量只显示谁和谁属于一起；名称来自配置或台账导入。
- **深度序列/嵌入模型、孤立森林、事件自编码器**：没有校准的尾部、没有有界的增量内存、没有逐约束的解释。
- **完整正则语言推断（RPNI、L\*）**：需要反例或查询；字符类反统一对取值形状已足够且有界。
- **精确函数依赖发现（TANE、FUN）**：对属性数指数级；筛选候选对 + g3 足够。
- **用 HMM / GMM 学时间窗**：Bayesian Blocks 参数少，对分段常数速率在有界样本上精确最优。
- **模式树回滚**：无法廉价重放；改为延迟学习、信任门控、暂存事件、多日确认与参考快照。
- **对每个策略选项做 A/B 运行**：多数维度可经前序码长全信息度量，只在引擎必须实际运行才能度量时才用老虎机。

#### 3.12.2 统计引擎库：与 v1 的差异及放弃的方案（详见 `docs/lib3/decisions.md`）

v1 的 7 个引擎（feature_vector、baseline、fingerprint、clustering、anomaly、drift、sequence）已删除：
每次重拟合的孤立森林（训练于攻击行、样本内 8% 尾部）→ 门控稳健 T²/SPE + RBC；KMeans + z 阈值命名 → 两级 HDBSCAN；
余弦漂移与最近邻余弦可分性 → B14 序贯变点与 B15 交叉验证 EER；基于 `behavior.z` 的身份 → 绝对表示；ACAT → wHMP；
确定性保形 → 随机化保形；按拍的阈值 → 墙钟 ARL；0.5σ/天的单一移动基线 → 0.1σ15/0.03σ15 双锚点 + 回滚；
可被投毒的自适应 L_ref → 固定 60；以风险关闭事件 → 以状态、累积器与证据关闭。深度模型（DeepLog、LogBERT、AE/VAE、对比学习、GNN）
在 20–40 个实体、每实体每周 10³–10⁴ 会话、无 GPU、< 100 ms/拍、需要校准尾部与廉价回滚的约束下不采用；学习型嵌入作为 P2 的 B22（PPMI-SVD ≡ SGNS）保留升级路径。

## 库四：行为特征库（Behavior Signature Library）

**定位**：不同指标组合“代表什么意思”的**预设库**，用于识别“用户可能在干什么”。
可枚举、数据驱动。拆分为 2 个匹配引擎（`backend/app/engines/signature/`）：

| 引擎 | 职责 |
|---|---|
| `signature.rule_match` | 对每个实体的**新鲜**指标快照（只取当拍写入的值，且只取特征引用到的指标名）评估全部在范围内的特征；条件支持硬判定与**模糊隶属(soft 容差带)**，置信 = AND 隶属加权均 × 最佳 OR 隶属 × 权重，受 NONE 门控；产出 `SignatureMatch` |
| `signature.correlation` | 把原子命中按**时序**组合成高层活动：`sequence`(有序、窗口内) / `cooccur`(并发)，置信 = 各构件置信之积；同样数据驱动 |

**节拍不变的计数子句（规范模式，第三轮修复）**：可加计数（`http.requests`、`l4.bytes_up`、`l4.flows`、`dns.queries` 等，见
`rule_match.ADDITIVE_COUNTERS`）按**每 15 分钟粒度的总量**读取：Δt < 900 时取尾随 900 s 之和（跨界拍按比例），Δt ≥ 900 时按 900/Δt 缩放，
不足一个粒度的新实体按已观测跨度折算。阈值因此保持其在 900 s 下的含义（`c2_beacon` 的 `http.requests ≤ 10` 不再在 60 s 下每拍命中 30 s 轮询的健康检查）。
去重计数不可加，仍按拍读取。tick 模式保留 v2 的逐拍读取（黄金参考）。

**特征定义 schema**（`data/signatures/primitives.yaml`，24 条原子特征）：
```yaml
- id: bulk_upload
  label: "批量上传/数据外发"
  category: transfer          # 语义类别
  severity: high
  all:                        # 全部满足(AND)，soft 给模糊带
    - {metric: l4.bytes_up, op: gt, value: 3000000, soft: 2000000}
    - {metric: derived.upload_dominance, op: gt, value: 3, soft: 2}
  none:                       # 排除项(NOT)
    - {metric: derived.timing_regularity, op: ge, value: 0.8}  # 排除计划备份
```
字段还有 `any`（OR）、`weight`、`scope`（适用的业务系统，空 = 全部）；
`op ∈ gt/ge/lt/le/eq/ne/between/in/not_in/present`。metric 指向快照中的原始/次生指标名——匹配引擎**无需知道值的来源**。

**原子特征**（24 条）：interactive_browse、search_query、form_submit_write、api_client、system_integration、auth_login、**auth_bruteforce**、
bulk_download、bulk_upload、large_object_fetch、streaming_media、**port_scan**、**host_sweep**、**web_path_fuzzing**、**c2_beacon**、**dns_tunnel**、
**dga_resolution**、weak_tls、service_degraded、high_error_backend、tcp_health_poor、health_check、backup_sync、admin_operation；
语义类别：browse/search/write/api/integration/auth/transfer/streaming/scan/recon/beacon/tunnel/posture/health/maintenance/sync/admin。

**组合特征**（`data/signatures/composite.yaml`，5 条）：staging_then_exfil（认证后短时批量外发）、recon_then_scan（资产枚举后端口扫描）、
beacon_with_tunnel（信标与隐蔽信道并发）、scan_then_bruteforce（扫描后认证爆破）、admin_then_bulk（运维操作后大批量数据搬运）。

**与行为库的关系**：渐进内核的违规与事件单经 B25–B28 与库四命中共同决定严重度；规格中 P03 向库四提供 `pat.violations.<类型>`、`pat.conformity` 输入（配置 `progressive.lib4_inputs`）以组合“谁违规之后批量下载”一类特征，**尚未实现**。库四命中以一拍滞后进入 B05（排除共模剔除）、B08（类别维度）、B10（类别多标签流）、B26（风险，习惯性 ≤ medium 命中权重 0）、
B27（证据，习惯性命中不重启静默时钟）、B28（库四 ≥ high 为 −2.3 的对数似然比项，训练期 trust 置 0）。

> 前端「行为特征库」页可检索、查看每条的条件与语义。

- v2（`backend/app/api/routes_v2.py`、`views.py`）：实体画像/画像差异/时间线/分数/身份，类列表与类详情，事件单列表与详情，
  事件单与事件的反馈写入，标签队列，系统摘要，检测器健康，评估报告，内存报告（完整列表见 README）。
- v3（`backend/app/api/routes_v3.py`、`progressive_views.py`）：渐进画像内核的系统视角、群组视角、IP 视角、精度随时间、模式格与模式详情、违例、侧面、策略、属性注册表、预算，以及群组命名（3.3.14）。

### 前端（`frontend/`，零依赖原生 JS + 内联 SVG，离线可用）
十个视图：总览、实体画像（画像卡与叙述、7×24 节律热图、按粒度的工作量带、客户端栈、模板与 n-gram、可辨识度与易混淆、风险时间线）、
类画像、事件队列（e_day 释义、按族/轴证据、反事实、反馈按钮）、系统视图（共模、活动、检测器健康）、行为事件、行为特征库、指标库、引擎拓扑、评估报告。
“画像模式”页（`js/progressive.js`）：两种视角加 IP 视角、精度随时间、模式格浏览与模式详情（谱系、漂移历史）、违例、多维刻面、系统特征与策略、属性注册表、资源预算（3.3.14）。

### 部署与扩展
- 水平扩展：按业务系统/网段分片流水线；存储层替换为分布式时序库；学习器状态经 `put_model` 持久化，可重启恢复。
- 新增能力 = 新增一个引擎并注册；新增检测器 = 在 `lib/detectors.py` 登记族/种类/流；新增语义 = 改 `data/signatures/*.yaml`；
  新增画像侧面 = 任一引擎把侧面声明写入 `model.facets`（P13 无需改代码）。
- 新增指标：渐进内核**无需改代码**——新的 Observation 字段、`extra.meta` 键、请求头或原始/次生指标名在出现的那一拍由 P02 登记、在线定型，
  由 P05 决定角色（3.3.3）；统计引擎库的固定特征表仍需改 `lib/features.py`。
